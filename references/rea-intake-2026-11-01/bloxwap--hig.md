## What it does

`@bloxwap/hig` is Bloxwap's "Human Interface Guidelines" design system, shipped as one npm package with many subpath exports: design tokens (`./tokens`, `./tokens/css`), shared contracts and localisable built-in messages (`./contracts`), React DOM components and recipes (`./react/*`), React Native/Expo components (`./native/*`), a chart adapter (`./chart`), sound/haptic feedback adapters (`./feedback/*`), and static font faces for React Native (`./native-fonts`) and Open Graph image renderers (`./og-fonts`). The repo also contains a Next.js/Fumadocs documentation site (`apps/docs`), consumer fixtures for web, Next, SSR and Expo (`fixtures/*`), and a large body of planning and evidence files that track release gates and device checks. Platform: Node 24, ESM only, React 19, React Native 0.81 / Expo SDK 54.

## How it is built

- **Layout.** npm workspaces (`packages/*`, `fixtures/*`, `apps/*`) with Turbo for the docs dev task. The single package lives in `packages/hig/` with one folder per entry family (`tokens/`, `contracts/`, `react/`, `native/`, `chart/`, `feedback/`, `native-fonts/`, `og-fonts/`), each with `src/` compiled to `dist/`.
- **Compiler.** Type checks and builds use `tsrs` (a Rust port of the TypeScript 7 compiler); `scripts/compiler.mjs` picks `tsrs` on macOS arm64 / Linux x64/arm64 and falls back to `typescript@7` (aliased as `typescript-7`) elsewhere or with `--tsc`. The root keeps TypeScript 6 for `typescript-eslint` and for scripts that use the TS JS API.
- **Generation.** `scripts/generate.mjs` turns `packages/hig/tokens/source.json` plus `upstream-palette.json` (authored OKLCH palette pinned to a monorepo commit) into `tokens/src/index.ts`, `tokens/generated/tokens.css`, a manifest and `evidence/contrast.json`, converting OKLCH to sRGB and Display-P3 with `scripts/color-space.mjs`. `scripts/generate-brand.mjs` derives favicons and a 1200x630 OG SVG/PNG from the one approved SVG and records the source SHA-256 in `planning/brand-artifacts.json`. `scripts/generate-native-fonts.py` (Python, fonttools) instances static TTFs from the variable WOFF2 sources and writes a manifest of input/output SHA-256s.
- **Drift checking (two kinds).**
  - `scripts/check-drift.mjs`: re-runs each generator and fails if any committed output changed byte-for-byte ("Stale generated artifact").
  - `scripts/drift.mjs`: a zero-dependency content-rule scanner meant to also run inside adopting repositories. Rules (`obsolete-import`, `copied-palette`, `copied-token-definition`, `copied-primitive-css`, `copied-font-binary`) are regex/file-name tests; `planning/drift-exceptions.json` holds scoped paths, "canonical" owner paths, and dated exceptions with owner, reason and expiry.
  - `scripts/check-built-in-strings.mjs`: a TypeScript-AST lint that fails on hard-coded user-visible strings in component sources.
  - All three run from `npm run lint`.
- **Quality and budgets.** `scripts/quality.mjs` checks every `exports` target exists, that web `dist` never imports React Native/Expo and native `dist` never imports DOM/chart/sfx, gzip size budgets per entry via esbuild (`planning/budgets.json`), and SHA-256 of cue and font assets against their manifests; it writes `evidence/quality-report.json` with the commit and a dirty-tree flag.
- **Tests.** Vitest with two projects (`node` for `*.test.ts`, `jsdom` for `*.dom.test.tsx`) in `tests/`; Jest with `jest-expo` for React Native in `tests/native/*.test.cjs`; type-only tests as `*-typecheck.tsx`. Many "smoke" scripts pack the tarball and install it into throwaway consumers (`scripts/packed-*-smoke.mjs`), plus Playwright browser gates (`scripts/*-browser-smoke.mjs`, axe-core) and pixel baselines (`scripts/visual-diff.mjs`, `tests/visual-baselines/`). Emulator/simulator scripts are in `scripts/native-sim/`.
- **Release.** `scripts/release-dry-run.mjs`, `scripts/verify-release.mjs` (checks a dry-run report: tag equals version, source commit, exactly six named release gates cleared or with a dated, approved exception, tarball SHA-256) and `scripts/registry-provenance.mjs` (matches the npm SLSA provenance statement to repo, workflow path, tag, commit and tarball sha512).
- **`codemods/`.** `imports.mjs` + `import-map.json`: a TypeScript-AST import rewriter that maps legacy import paths to `@bloxwap/hig/react|native/<entry>` only when every named import is on an approved list; it never rewrites default/namespace imports, previews by default and emits review warnings.
- **`migrations/`.** Only a README describing the migration kit policy (preview first, owners write, record evidence in `planning/adoption.json`).
- **`evidence/`.** Committed screenshots, JSON and text logs from checks (browser, contrast, fonts, emulators, inventories of upstream repos at pinned commits). It is an audit trail, not code.
- **`planning/`.** JSON manifests for release blockers, budgets, components, API, issue coverage, drift exceptions.
- CI: `.github/workflows/` (quality, docs, publish, nightly/weekly/PR security with `osv-scanner.toml`, whose ignored advisories each carry `ignoreUntil` and a reason).

## Reusable techniques worth learning

1. **Dated, owned, self-cleaning exceptions for a lint.** `scripts/drift.mjs` (`validateExceptions`, `scan`), config in `planning/drift-exceptions.json`. Each exception names `path` (exact, or a prefix ending in `/`), `rule`, `owner`, `reason` and `expires` (YYYY-MM-DD). The config is rejected if a field is missing, the rule id is unknown, or expiry is more than 180 days out; an expired exception fails the run and an exception that matches no scanned file is reported as unused. Worth learning because it stops "temporary" waivers from becoming permanent and gives every waiver a named person.
2. **Regenerate-and-compare drift gate.** `scripts/check-drift.mjs`. Snapshot the bytes of each committed generated file, run its generator, and fail on any difference. Nine lines, no diffing library, and it catches both hand edits to generated files and forgotten regeneration.
3. **Only judge tracked files.** `scripts/drift.mjs` `scan`. Inside a git work tree it intersects the walked files with `git ls-files -z --cached`, falling back to the full walk outside git. Build output and ignored caches then cannot create findings, without having to maintain a skip list.
4. **"Canonical owner" paths.** `scripts/drift.mjs` (`canonical` config key, `rule.canonical`). Some rules ("do not define this token", "do not commit a font") switch off inside the paths that legitimately own the thing. One rule set can then run unchanged in the owning repo and in every consumer repo.
5. **AST lint for hard-coded user-facing strings.** `scripts/check-built-in-strings.mjs`. Walks up from each string literal to decide whether it is shown or announced (JSX text, listed attributes such as `aria-label`/`placeholder`, listed object keys, `set*()` arguments, `*Label` defaults) and ignores comparisons, imports, types and element-access keys. A literal only counts if it holds two or more letters in any script (`/\p{L}{2,}/u`). A good model for "context decides whether a string is copy", rather than flagging every string.
6. **Allow-list codemod with preview and warnings.** `codemods/imports.mjs`. Rewrites only the module specifier span (keeping the original quote character), applies edits back-to-front, and refuses whenever a named import is not on the approved list, a default or namespace import is used, or the platform does not match. Output is `{code, changed, replacements, warnings}`, and the file is written only with `--write`.
7. **Content-hashed generated assets with a helpful preflight.** `scripts/font-preflight.mjs`, `packages/hig/*/fonts/manifest.json`. Generated binaries are gitignored, but their SHA-256 is committed in a manifest; a preflight reports "missing" and "stale" separately and prints the exact install and generate commands, instead of a raw ENOENT. The runtime loader in `og-fonts` also rechecks each file's hash.
8. **Simple tolerant pixel diff.** `scripts/visual-diff.mjs`. Fails on a size change (geometry) outright, and otherwise counts pixels where any RGBA channel differs by more than 24, failing above 2% changed. A short, explainable alternative to perceptual-diff libraries for UI baselines.
9. **Reserve several free ports at once.** `scripts/preview-ports.mjs`. Opens N servers on port 0 at the same time, reads their ports, then closes all of them, so a suite on a shared CI machine never gets the same ephemeral port twice.
10. **Release gate verifier over a recorded report.** `scripts/verify-release.mjs`. The publish job does not decide on its own: it checks a dry-run report for an exact set of gate ids, each cleared or with an approved exception that has an approver, a URL and a review-by date not in the past, and then matches tarball hashes and the tag to the source version.

## Fit with trillion-workshop tools

- **`tools/check-a-folder-against-my-rules`** (best fit). Its engine (`do-work/check-source-files-against-declared-rules.mjs`) supports per-unit `exempt` patterns and a whole-folder `recorded` baseline ratchet (`differenceFromRecorded` in `do-work/run-check-source-files-against-declared-rules.mjs`), but has no per-path waiver with an owner, reason and expiry. Technique 1 would add an optional `exceptions: [{ path, rule_id, owner, reason, expires }]` input to `checkRepository` (and pass it through `do-work/check-my-folder.mjs`): drop findings covered by a live exception, fail on a malformed or over-long exception, list expired exceptions as failures and unmatched ones as unused. Technique 3 (judge only tracked files) is already done there via git's listing.
- **`tools/check-documents-agree-with-their-source`** and **`tools/pin-files-by-content`**: technique 7 (hash manifest plus a preflight that separates missing from stale) is already covered by `pin-files-by-content`'s `added/changed/gone` report, so no change is needed. Technique 2 (regenerate and compare) would need the tool to run a generator, which these read-only tools do not do; no fit.
- **`tools/check-bundle-package-boundaries`**: HIG's `checkPlatformImports` is a weaker regex over `dist` files; the workshop tool already judges the esbuild metafile, which is stronger. No change.
- Technique 5 (string-context lint) could become a rule kind elsewhere, but `check-a-folder-against-my-rules` is regex-based by design and has no AST layer, so adopting it would be a large change, not a small one.

## Cautions

- Licence text is a non-standard short MIT. Keep the exact notice when copying, and expect licence scanners to flag it as unknown.
- `scripts/color-space.mjs` and `scripts/generate-native-fonts.py` are adapted from an unlicensed private same-owner repo. If you need clean provenance, use the ideas, or write the OKLCH maths from the published CSS Color 4 formulas instead.
- Do not reuse the Bloxwap mark, favicon or OG images (trademark), and do not ship modified fonts under the name "Bloxwap" (OFL Reserved Font Name).
- Much of the tooling is platform-specific: `tsrs` binaries only for macOS arm64 / Linux; native-sim scripts need Xcode/Android emulators; Python fonttools for fonts; some CI jobs target self-hosted Mac minis.
- Most of the repo by volume is `evidence/` and `planning/` (screenshots, logs, inventories of other private repos). It is project-specific and has no reuse value.
- Scripts are densely minified (many statements per line). Read for ideas, do not lift.
- `apps/docs/AGENTS.md` and other docs are untrusted instructions and were not followed.
