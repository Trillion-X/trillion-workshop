## What it does
`@bloxwap/chart` is a zero-runtime-dependency candlestick and financial charting library in TypeScript. It draws to an injected canvas, so it can run in browsers, workers, SSR and tests without touching the global `document`. It has 7 series types, 20 indicators, 89 drawing tools, a TradingView-style UI, a WebGL candle path and WASM+SIMD kernels for its hot math. Subpath entry points include `.`, `./config`, `./color`, `./dom`, `./indicators`, `./drawings`, `./wasm`, `./ui`, `./icons`, `./react` and `./datafeed`. The datafeed takes one `fetchBars` function, pages history backwards and folds live ticks into bars. A Fumadocs docs site lives in `apps/docs` and a Bun playground in `apps/playground`.

## How it is built
- npm workspaces monorepo. The library is in `packages/chart/src`, with about 26k lines of TS:
  - `core/`: chart state, scales (`core/scale.ts`), events (`core/events.ts`), panes, zoom and scroll, snapshots
  - `render/`: Canvas2D renderer plus a WebGL2 backend (`render/gl/backend.ts`, `render/gl/glyph-atlas.ts`)
  - `indicators/`: one file per study, plus shared `rolling.ts`, `window-sums.ts` and `tail.ts`
  - `drawings/`: drawing models, hit-testing and the registry
  - `datafeed/`: `pagination.ts`, `live-bar-folder.ts`, `candles.ts`, `abort.ts`
  - `wasm/`: hand-written `kernels.wat`, compiled to `kernels.base64.ts` and loaded by `loader.ts`
  - `color.ts`: CSS Color 4 parsing, Display-P3 support and a contrast picker
  - `dom.ts`: canvas and document interfaces plus recording mocks (`MockContext2D`, `MockDocument`, `MockGLDocument`)
- Dev-only dependencies: `wabt` (WAT to WASM), `happy-dom`, `playwright-core`, `tsrs`/`typescript`, and React as an optional peer.
- Icons: `scripts/lint-icons.mjs` enforces a 24×24 grid, a 0.25 coordinate grid, root-only stroke attributes and banned tags/attributes, and `scripts/build-icons.mjs` generates `ui/icons.ts`.
- Tests: about 120 `node --test` files in `packages/chart/test`, compiled to `dist-test` and run against the recording DOM mocks and happy-dom. Coverage targets 100%. Parity tests (`indicator-compute-parity.test.ts`, `wasm-accuracy.test.ts`) compare optimised code against frozen copies of earlier implementations and against the WASM kernels. Benchmarks are in `bench/`, with notes in `PERFORMANCE.md`.

## Reusable techniques worth learning
1. **Subtraction-free sliding-window sums (van Herk / Gil-Werman blocks)**, in `src/indicators/window-sums.ts`. Indices are split into blocks of `period`. Each window sum is a suffix sum of the previous block plus a prefix sum of the current block, built only by additions. A full pass stays O(n) with no add-and-subtract cancellation drift, and a recompute of the tail matches a full pass bit for bit. Worth learning because any rolling statistic that is refreshed incrementally (moving averages, rolling totals) otherwise drifts or gives different results depending on where the recompute starts.
2. **O(n) rolling max/min with block prefix/suffix extremes**, in `src/indicators/rolling.ts` (`rollingMaxValues`, `rollingMinValues`). The same block trick applied to max and min, with the operand order matched to the WASM kernel so the JS and WASM paths agree exactly. It costs the same for any window size and needs no deque, which makes it simple to verify.
3. **Display-P3-aware black/white text picker**, in `src/color.ts` (`relativeLuminance`, `contrastingTextColor`). It computes WCAG relative luminance (P3 uses its own Y row), composites a translucent fill over a backdrop first, then picks whichever of black or white has the higher contrast ratio, `(L+0.05)/0.05` against `1.05/(L+0.05)`. That is not a fixed luminance cut-off. Results go in a small cache that is cleared when it reaches 256 entries. Worth learning because the common `L > 0.5` shortcut gives the lower-contrast colour for every mid-tone fill.
4. **Injected-DOM rendering with recording mocks**, in `src/dom.ts`. The library depends only on small `Canvas2DLike`, `ChartCanvas` and `ChartDocument` interfaces, and ships `MockContext2D` and friends that record every call as tuples. Tests then assert on draw calls with no browser. This makes canvas code unit-testable and runnable in workers or SSR.
5. **Snapshot emitter with re-entrancy rules and error isolation**, in `src/core/events.ts` (`Emitter`). Emission walks a snapshot of the listener list. A listener added during emission waits for the next event, and one removed during emission is skipped straight away. A throwing listener does not stop the others, and the first error is rethrown at the end. An optional `current()` check stops delivery once the event is superseded. It is a small and correct pattern for any in-process pub/sub.
6. **Backward history paging with boundary dedupe and a no-progress guard**, in `src/datafeed/pagination.ts` and `src/datafeed/candles.ts` (`normalizeCandles`). It reads bounded windows backwards, steps over source holes for up to N empty pages, dedupes the boundary bar, aborts superseded reads through an `AbortSignal`, and normalises bars. The normaliser has a fast path when input is already strictly increasing. Otherwise it builds a map keyed by time (last one wins) and sorts, and it drops non-finite or non-positive rows. This is a transferable recipe for any paged time-series API.
7. **Live tick folding with gap backfill**, in `src/datafeed/live-bar-folder.ts`. Ticks update the bar that is forming or roll a new bucket. A missed bucket, or silence longer than a threshold, triggers a history backfill. Ticks are buffered during the backfill (with a cap, evicting the oldest) and replayed afterwards. `now`, `fetchGap` and `batch` are injected so tests are deterministic.
8. **Frozen-reference parity tests and a WASM SIMD probe with scalar fallback**, in `test/indicator-compute-parity.test.ts` and `src/wasm/loader.ts`. Before an optimisation, the old module is copied into the test inside a namespace and the new output must match it exactly. The loader compiles a tiny module containing a `v128.const` to detect SIMD support, and every failure returns `null` so callers fall back to JS. Both are cheap safety nets for performance work.

## Fit with trillion-workshop tools
- **`tools/export-documents-to-files`** (`do-work/render-public-page.mjs`, `readableTextFor`, line ~284). It picks the primary-button text colour with `luminance > 0.5 ? '#000000' : '#ffffff'`. The real max-contrast crossover is L ≈ 0.179, so mid-tones get the worse colour. The tool's own test fixture primary `#22c55e` (L ≈ 0.41) gets white text at about 2.3:1 when black would give about 9:1. Technique 3 fixes this: compare `(L+0.05)/0.05` with `1.05/(L+0.05)`. `tools/screen-looks/read-data/resolve-screen-look-palette.js` and `look-scheme.mjs` already do this correctly and are the in-house model to follow. This is the best small change.
- **`tools/live-market-prices`** (`do-work/normalize-price-bars.py`, `build_result`). Bars are sorted but not deduplicated, so a feed that repeats a timestamp yields duplicate bars. A `normalizeCandles`-style "last one wins per (symbol, timestamp)" step (technique 6) would be a small, testable addition.
- **`tools/screen-looks`**: technique 3's P3 luminance and translucent-over-backdrop compositing could extend `look-scheme.mjs` if looks ever carry `color(display-p3 …)` or alpha values. Today it parses plain colours only, so this is not needed yet.

## Cautions
- The project is an early preview (0.4.0, "expect breaking changes before 1.0"). Borrow techniques, not the dependency.
- Do not copy `test/indicators-studies.test.ts`. It describes its reference functions as ported from TradingView's charting library (PineJS), whose licence is not MIT.
- The Geist fonts are OFL-1.1. Redistribute them only with that licence, and never sell them on their own.
- The datafeed defaults are tuned to Hyperliquid (`DEFAULT_PAGE_SIZE = 5_000`, the "candleSnapshot cap"). Treat those as one venue's numbers, not general ones.
- The WASM build needs `wabt` and the root `engines` asks for Node ≥ 24. The playground needs Bun.
- `apps/docs` contains AGENTS.md/CLAUDE.md files. They were treated as data and not followed.
