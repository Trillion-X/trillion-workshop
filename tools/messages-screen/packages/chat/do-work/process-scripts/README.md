# chat/do-work/process-scripts

Process-script capabilities the chat package runs via `compute.process` to build its conversation surface.

## Files

| File | Purpose |
|------|---------|
| `materialize-conversations.py` | Reader-keyed materialization (Pattern 102/104) for the conversation sidebar: composes the `observe-file-glob` observer + `decode-jsonl-session` decoder over a self-contained set of observed-content source descriptors and projects the resulting threads into the canonical `chat-session-window` row shape. Owns NO format knowledge or file-walking — those live in the composed leaf capabilities. The only chat-specific layer speaks the sidebar's row vocabulary. |
| `materialize-transcript.py` | Bounded per-thread transcript page for `read-chat-session-transcript-page`: composes the descriptor-named decoder capability over the mounted thread feed and returns the paged `{atoms, older_cursor, ...}` window. Blind to source and to any egress vocabulary. On a FIRST-page read (`before_cursor is None`) it applies optional OPTIMISTIC outbound overlays via `apply_overlays` — each overlay pairs a literal descriptor with a bound `feed_mount`, decoded by the co-mounted CD adapter and converged into the native atoms by `transcript_mapper.converge_atoms`; missing overlay/import fails safe to the unchanged native page. Positional argv: `<sources.json> <out.json> <session_id> <file_path> <before_cursor> <limit> [overlays.json]`. |
| `__tests__/test_materialize_overlay_weave.py` | Proves the overlay weave end to end against the real module (optimistic send appears before the native echo, first-page-only application, byte-identical no-overlay fallback, fail-safe on missing feed/import). 10/10. |
| `decode_viewer_reactions.py` | Durable-readback decoder for the viewer-intent ledger: reads persisted annotation-intent records (reaction/pin/star/bookmark) and projects them into per-atom `MessageReaction` rows so an authored annotation converges from optimistic (provenance 0) to durable on reload. Blind to source; folds annotation kinds into the generic reaction atom. |
| `build-conversation-descriptors.py` | Expands the COMPACT transcript-source specs (the cli-registry `prop:cli_registry:transcript_sources` fold rows) into the FULL self-describing source descriptors the decode loop consumes. Handing a descriptor forward is NOT decoding it, and this step cannot know the difference, because only the leaf that runs the decoder can say what happened. |
| `decode-one-source.py` | The per-iteration leaf of the per-source decode loop: decodes ONE source descriptor into sidebar rows and writes `{decoded_source_ref, decode_status, rows}`. Blind (no channel branch, no decoder name, no mount filename); imports the decoder by the descriptor-derived name. Fail-closed per source: an unmounted decoder yields no rows and SAYS WHY instead of crashing the sidebar. Bounds its own output on three axes (row count, per-row bytes, hard total) so one large source cannot trap the workflow wasm. |
| `reduce-conversations.py` | The final blind reduce of that loop: concatenates, dedupes, sorts and windows the rows, and keeps a source's done-mark ONLY when it finds that source's own success. Marks from positive success, never by subtracting recognised failures. Reads outcomes from a CLOSED set of wrapper shapes and never descends into content, because content is the part an outside source gets to choose. |
| `__tests__/test_per_source_decode_loop.py` | Proves the decode and reduce contract against the real modules: healthy publication, empty-but-successful sources, missing decoders, malformed and partial rows, and self-contradicting sources. Every refusal is asserted beside a must-publish control, so a reducer that simply published nothing would fail too. |
| `decode-addressed-exchange.py` | Leaf decode capability for the chat package's OWN live-conversation store: reads the addressed-exchange conversation ledger written by `do-work/write-addressed-exchange-ledger.ts` at `package::chat::conversation-ledger::{index,conversation::<id>,turn::<id>}` and projects it through the same descriptor-named decoder seam as any external source. |
| `expand-connected-source-descriptors.py` | Expands provider-neutral source templates over usable service connections. The source row owns provider knowledge as DATA; this transform understands only the canonical service-connection record and `${connection.*}` bindings. Pure: two JSON inputs become one JSON output, with no network, vault, or file-discovery side effects. |
| `observe-inline.py` | Generic acquisition capability for sources whose observations are PROVIDED to the materialize process, either inline on the descriptor (pure data and tests) or in a mounted file the descriptor's location names (the live path). The engine-record analogue of `observe_file_glob`. |
| `noop-overlay-decoder.py` | The removable-capability floor for the optional egress overlay (L063/L112). The optimistic just-sent echo is owned by whichever egress package is installed; when that package is not in the running set its decoder bytes are absent. A missing OPTIONAL enrichment must degrade to "no optimistic atom" rather than fail the page, and this file is what it degrades to. |
| `publish-send-route-participants.py` | Publishes addressed-exchange participant records for conversation receivers that can accept sends. For each conversation carrying BOTH `sendCapability` (routing metadata) AND `sendRef` (resolved handle), emits a `ReachableEndpoint`-shape record. |
| `resolve-transcript-owner.py` | Picks the ONE decoder that owns a transcript page's `file_path` and emits the byte-delivery pair the page def needs to mount exactly that decoder, nothing else. The enum-dissolution seam for the transcript page read: the def used to statically read and mount five per-channel decoder scripts. |
| retired fused scanner | Deleted. Source discovery and decoding now compose through observed-content descriptors, file-glob observer capabilities, JSONL decoder capabilities, and reader-keyed materializers. |

## Key Types / Functions

| Type | Signature / Shape | Role |
|------|-------------------|------|
| `materialize(sources, per_source_limit)` | `(list[descriptor], int) -> chat-session-window` | Observe → decode → map threads → rows; sort newest-first. |
| `thread_to_row(thread, source_ref)` | `(dict, str) -> row` | Project a content-atom thread into the sidebar row (`recordId, sessionId, executorRef, title, prompt, startedAt, lastActivityAt, messageCount, filePath, sourcePresent, lastMessagePreview`). |
| output window | `{version, window_key:"latest", limit, total_count, total_count_known, rows[], has_older}` | Exactly the payload `read-chat-sessions.ts` `decodeActiveChatSessionWindowPayload` reads at `chat-session-window:latest`. |
| leaf outcome | `{decoded_source_ref: str, decode_status: str, rows: list}` | What `decode-one-source.py` writes per source. `decode_status` comes from the materializer and is one of `decoded`, `capability-not-installed`, `no-source-ref`. The envelope NAMES ITS SOURCE and SAYS WHAT HAPPENED, so an empty source is distinguishable from an unreadable one. |
| reduce status | `DECODED` \| `PARTIAL` \| `FAILED` | The reduce step's own CLOSED three-state alphabet, and the only values `_entries_in` may emit. Everything the leaf reports maps into it: a well-formed success whose rows are all rows is `DECODED`; a success carrying a non-row is `PARTIAL`; `capability-not-installed`, `no-source-ref`, anything malformed, and a tolerated error are all `FAILED`. `_marks_from` REFUSES any value outside these three rather than treating an unrecognised status as "not a failure". |
| mark and publish rule | `(marked, disbelieved)` | `DECODED` exactly once and nothing else said about that source earns the mark. A `FAILED` anywhere, or two `DECODED`s, disbelieves the source so even its successful entry's rows are withheld. A `PARTIAL` sits between: no mark, so it retries, but its readable rows still reach the screen, because one malformed record should not blank a source. |

## Dependencies

- **Depends on:** `file-glob-observer` (`observe_file_glob.observe`), `jsonl-session-decoder` (`decode_jsonl_session_events.decode`) — both mounted alongside as importable modules by the composing workflow def; observed-content source descriptors (DATA, self-contained source-set).
- **Depended on by:** the `chat-session-window` materialization def (composes these scripts via `compute.process`); the sidebar reads the resulting `chat-session-window:latest` via `read-data/use-chat-conversation-records.ts`.
