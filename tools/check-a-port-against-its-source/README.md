# tools/check-a-port-against-its-source/

Checks a contract for work taken from a reference: a source ported, a behaviour ported, a visual replica, an inspiration or an anti-reference. It verifies the declared source, baseline, target, preserved mechanisms and, for a replica, the measured geometry and the pixel difference, without knowing which application uses the contract. Ported from the package `reference-adaptation-contract`.

It is also the one judge of a repository's feature code: every feature file a change adds, or grows past a number of lines, must be claimed by a valid contract. Either it ports an older owner, named by repository, commit and path, whose first commit here was the exact byte copy and whose lines it still carries (a rewrite of an existing job fails both), and the old copy leaves its repository within a few days (one copy of a job); or it claims `NO_PRIOR_OWNER` with the capability search and the code search that found no owner, and the judge runs that search again at the moment it judges. The same judge runs at a commit (the staged index), at a push or a pull request (the range) and in a repository's own test (everything since its rules began). Which files are feature files, where contracts live and which modes count are DATA the repository carries (`ports/feature-files.json`, this repository's too), so a session that only sees that repository is judged by the same rules.

All contract, source, picture and comparison identities are the BLAKE3 identity `1f:<64 hex>` of `tools/content-identity`, the one owner. Application identity, source paths, target paths and adaptation choices stay DATA in the contract the person gives.

For a `NO_PRIOR_OWNER` search, each `proof.search.repositories` row records `commit` and exactly one of `repository` or `repository_multihash`. The latter is the content identity of the UTF-8 repository name. It resolves only against the reader's own repository, explicitly supplied repository mappings and the caller's required search names. It does not discover directories or grant access. Unknown, malformed, duplicate and conflicting locators are refused; every required repository must still be covered. Ordinary spaces in an explicitly authorized name keep their meaning.

Both locator forms verify that the captured commit is an immutable object readable through that declared checkout. An unavailable reader is reported as deferred. A historical capture can remain readable after its branch or published main changes; current-main ancestry is not a prerequisite. These checks verify the reference, not that a past query occurred. The fresh code searches still run against current published snapshots and return their actual commits in `measurements.searched`, separately from the preserved capture.

Under the same contract schema, `sources[].repository` accepts either the existing name string or the closed object `{ "repository_multihash": "1f:<64 hex>" }`. A typed name resolves only against self, explicit `repositories` mappings and `repositoryNames` supplied to `gitReaders`; the repository judge supplies its caller-declared `searchRepositories` as those names. No directory scan or inferred alias resolves a hash. Unknown or ambiguous names defer the source read. Source labels show the hash, and repository comparisons use that same identity for full-artifact origins, in-place history and retirement. Self retirement reads the judged candidate; external retirement still requires published main. Source commits, ranges, baselines, deadlines, rights and status checks are unchanged.

`NO_PRIOR_OWNER` explanations in `distinct_from[].repository` accept the same name string or closed typed object. They match only that repository's actual search hits, still require `why`, and preserve exact-file and directory-path bounds. A typed explanation does not replace the captured search commits or the fresh searches.

Feature coverage and target admission are separate. The existing feature rules still select which changed files need contracts and which files can supply retention and mechanisms. Every declared target must also be readable as a current regular file, so coupled JSON or other DATA can accompany code without expanding feature coverage or supplying archived source lines. A contract's own explicit `baseline.path` identifies its separate artifact; a legacy archive-first target outside the feature scope is likewise refused. Neither can supply that contract's retention or mechanisms. A path named as another contract's historical baseline is not evidence that the path is archival in the current tree.

An in-place source can follow actual Git renames from its original pre-policy snapshot to the current target. Each contributing branch must trace unique moves back to that same original file; branches can use different intermediate names. Matching bytes or a copy-group history are insufficient. The witness refuses ambiguous move outputs, unrelated destination history and incomplete history; the validator still requires a one-to-one complete source/target set, the original pre-policy commit, and all earlier and parallel history checks. A staged judgment includes actual index rename records and every pending merge parent's history; changing the index or the ordered parents during the judgment refuses it.

Typed quotation consumers can call `validateReferenceAdaptationEvidence(contract, options)` with real repository readers. It shares the full validator's structural, literal-copy/mode, pinned source, line-range, redaction and declared copy-identity checks. Its result carries `scope: "immutable-contract-evidence"` and `admission: false`; full admission separately checks current targets, retirement, completed baseline copies, history and retention. The quotation consumer also binds the quote's exact bytes through the existing BLAKE3 owner. `NO_PRIOR_OWNER` requires fresh searches and is refused by this evidence endpoint.

For one immutable repository source, `SOURCE_FIRST_PORT` also accepts `baseline.redactions: [{ from_bytes: [start, end], to }]`. These are zero-based UTF-8 byte offsets into the original source bytes, with an exclusive end. When `source.lines: [first, last]` selects a range, offsets are relative to that selection, and its exact raw bytes and hash are used. The line range must be exactly two safe integers, one-based and inclusive. Selection preserves CRLF, BOM and a missing final newline; malformed UTF-8 is refused before selection. The source hash must match before any offset is used. Ranges must be ordered, nonempty, disjoint and on UTF-8 boundaries; replacements must be valid UTF-8 text. Multiple sources, mixed literal/byte forms and malformed arrays are refused. All declarations are checked before the copy is assembled. The metadata contains neither the removed text nor an extra digest of a private fragment; positions and lengths remain visible.

For this byte form, `source.multihash` and `baseline.source_multihash` identify the unredacted selected bytes, or the entire source when no lines are selected. Retention is measured against that original text. Only the copy-identity comparison uses the transformed bytes and `baseline.target_multihash_at_baseline`; a whole-file baseline cannot replace a redacted selection's exact copy. Existing literal `{ from, to }` replacements retain their sequential behavior. Neither form proves privacy readiness, completed copying, current adoption or source history: the actual serialized contract and copied bytes still need the privacy gate, and all existing chronology, ownership, retirement and active-source checks remain.

A separate `baseline.path` can hold the complete, unredacted original file when the first source selects `lines`. All source references must name the same repository, commit and path (or path multihash), and the complete artifact must match those pinned source bytes. `baseline.target_multihash_at_baseline` then identifies the complete artifact; the source identities and `baseline.source_multihash` still identify the selected ranges. The existing history checks still apply. Line retention and required mechanisms still come from active targets.

History proof checks every relevant content event not strictly descended from the baseline, including incomparable branches and earlier names. Independent original copies can merge before adaptation; a parallel adaptation still fails after a revert, deletion or merge that discards it. The reader explicitly certifies this coverage, including root commits, so an older reader cannot silently supply an incomplete proof. The existing pre-policy same-file exception keeps its ancestral-history allowance and also checks parallel content.

## A baseline at a different path

For a renamed port, optional `baseline.path` names the separate byte-copy artifact at `baseline.commit` in the target repository. It must be a non-empty repository-relative path with `/` separators and no empty, `.` or `..` segments, backslashes, colons or control characters. A repository reader must verify a regular file at that exact path and commit against the declared baseline BLAKE3 identity. An absent path, wrong bytes, symlink or invented commit fails even when the active target currently equals the source. Source identities and declared literal redactions are checked as before.

The artifact is historical evidence, so it must not appear in `targets[]`. With `baseline.path`, active target paths must use the same canonical repository-relative form and must be readable at either stage, preventing aliases such as `./proofs/source.mjs` from claiming the artifact under another spelling. Disk readers refuse file and parent symlink aliases; Git tree and index readers accept only regular files. Retention and required mechanisms use only the current active targets. The artifact may remain on disk or may have been renamed or removed after the baseline commit; neither state contributes retention. Multiple source files and multiple active targets still share the existing grouped retention measurement.

Every repository source-first baseline must precede adaptation in the real Git history, whether or not `baseline.path` is present. It must be an ancestor of the judged commit (or `HEAD` for disk and staged reads). Every active target must either have held only exact declared source copies up to that baseline, or have no path history at the baseline and be introduced afterward. Earlier same-file development is exempt only when the complete source and target sets are original in-place snapshots at the same baseline commit, no later than the judge's `policySince` anchor. Each snapshot must match its own baseline bytes. Mixed or post-policy self-sources cannot certify imported adaptation. An introduction on an unrelated branch cannot qualify by being merged later. A rewritten target, including one deleted or reverted before a later archival copy, fails. A fresh archive does not retroactively prove a source-first port.

History proof fails closed in shallow checkouts or repositories with legacy grafts. Readers ignore replacement objects so a local replacement commit cannot substitute for the declared immutable history.

Without `baseline.path`, the first target's path supplies the historical baseline, or the exact current target bytes prove the initial copy before a baseline commit exists. The same chronology checks apply to a committed baseline. `baseline.path` always requires committed proof and never uses that initial-copy shortcut. The repository judge and its command use the same validator; a caller without a repository reader cannot verify an explicit separate baseline.

For an initial uncommitted copy, every active target must still be exact declared source bytes and have no earlier adaptation history. A genuinely unborn repository has no prior target history. For a committed target rename, the reader may follow Git's rename records back to the baseline's earlier name, bounded by the judged commit. It checks all known names before and after the baseline, including a deleted and reintroduced current name. An unrelated new file cannot borrow another file's baseline, and an explicit `baseline.path` always requires that exact path rather than a rename fallback.

The judge supplies `activeTargetPaths` from all paths matching its feature-file DATA in the judged tree, including unchanged helpers, and `policySince` from those rules' original `since` commit. A non-feature artifact in `targets[]` is refused and supplies no retention or mechanisms. Direct callers may supply the same scope and policy anchor. A direct source-first contract with multiple targets and neither `baseline.path` nor `activeTargetPaths` is ambiguous: it fails and reports no retention measurement. This preserves grouped active ports without treating an archival copy as active code. The judge's own Git span and path discovery ignore replacement objects too, so replacements cannot hide files before the validator runs.

## Shared immutable reads and retirement

Each reader resolves one judged commit and builds one full, NUL-delimited raw Git history index for it, including every merge parent. Target checks share that graph, rename candidates and path events instead of rerunning `git log --follow` for every file. Byte-identical created outputs share conservative rename candidate groups, so an archive cannot hide earlier adaptation of the active output. Ambiguous former names with different baseline bytes remain unproved. The existing 256 MiB Git-output bound applies; an unreadable index never admits history.

Caches stay inside one reader and rights scope: eight tree snapshots with a 64 MiB estimated metadata budget, 64 MiB of blob bytes, and bounded ancestor, lineage and search entries. Public byte buffers and search results are copies. A new reader sees a new judged or published commit; filesystem target reads and shallow/graft refusal remain fresh. Code search caches the exact repository, resolved published main and pattern, while checking both file contents and filenames. The judge validates each loaded full contract once in its stable tree/options/time scope, then applies that result only to changed paths the contract actually claims.

Git reads bind to the declared checkout, clearing inherited repository, object and namespace selectors. Only staged reads use the caller's private `GIT_INDEX_FILE`; committed sources and external published searches ignore it. The judge uses these same scoped reads for changed features and contract discovery. Self shallow/graft overrides remain visible to its history guards, while external repositories use their own history view.

The judge freezes both range endpoints before reading its rules or paths, so a moving branch cannot change the diff after the file view is bound. Staged judgments freeze their `HEAD` baseline and index generation; an index change during discovery, validation or diff reading ends the judgment with an explicit error. Standalone staged readers still refresh their metadata when the index changes between reads.

`gitReaders().targetState(path)` exposes that reader's existing target inspection as `{ state: 'absent' | 'regular' | 'unreadable', mode?, bytes? }`. A known leaf mode uses Git's mode strings, such as `100644`, `100755`, `120000` or `040000`; a parent alias or unknown revision supplies no invented leaf mode. Only regular files supply copied bytes. The method checks judgment scope before and after inspection, and a standalone staged read whose index changes during inspection returns unreadable. `readTarget(path)` keeps its existing `Buffer | null` interface, and retirement policy is unchanged.

For `old_copy` inside the judged repository, `retirementOf(source)` reads the candidate commit, staged index or current filesystem view. A source slice may leave a file while a compatibility facade remains; a whole-file move requires the old path to be absent. Absent, regular and unreadable/nonregular states stay distinct. Symlinks in the leaf or its parent chain, directories at the old file path and unreadable candidates supply no retirement proof. The staged metadata cache refreshes with the index generation and refuses a changing read. Other repositories still use their published main; local disk edits, staging or unpublished commits there do not retire their owners. `mainOf` and source/code searches keep their original published-main semantics.
