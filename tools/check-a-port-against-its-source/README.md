# tools/check-a-port-against-its-source/

Checks a contract for work taken from a reference: a source ported, a behaviour ported, a visual replica, an inspiration or an anti-reference. It verifies the declared source, baseline, target, preserved mechanisms and, for a replica, the measured geometry and the pixel difference, without knowing which application uses the contract. Ported from the package `reference-adaptation-contract`.

It is also the one judge of a repository's feature code: every feature file a change adds, or grows past a number of lines, must be claimed by a valid contract. Either it ports an older owner, named by repository, commit and path, whose first commit here was the exact byte copy and whose lines it still carries (a rewrite of an existing job fails both), and the old copy leaves its repository within a few days (one copy of a job); or it claims `NO_PRIOR_OWNER` with the capability search and the code search that found no owner, and the judge runs that search again at the moment it judges. The same judge runs at a commit (the staged index), at a push or a pull request (the range) and in a repository's own test (everything since its rules began). Which files are feature files, where contracts live and which modes count are DATA the repository carries (`ports/feature-files.json`, this repository's too), so a session that only sees that repository is judged by the same rules.

All contract, source, picture and comparison identities are the BLAKE3 identity `1f:<64 hex>` of `tools/content-identity`, the one owner. Application identity, source paths, target paths and adaptation choices stay DATA in the contract the person gives.

## Key Types / Functions

| Name | Signature | Role |
|------|-----------|------|
| `validateReferenceAdaptationContract` | `(contract, { stage?, target? }) -> { valid, errors, id, mode, status, measurements }` | Never throws on a malformed contract: it returns errors in words. `stage` is `pre-edit` or `completion` (the default). |
| Contract | `{ schema, id: "REF-...", status, directive, mode, sources, targets, preserve, allowed_deltas, banned_substitutions, baseline, proof }` | Mode is `SOURCE_FIRST_PORT`, `BEHAVIORAL_PORT`, `VISUAL_REPLICA`, `INSPIRATION_ONLY` or `ANTI_REFERENCE`. A copy directive cannot be relabelled inspiration. `baseline.redactions` (`[{ from, to }]`, literal replacements) lets the byte copy drop words that may not move into this repository (a private path, a person's name): the copy is then the source with exactly those replacements. |
| Repository source | `{ repository, commit, path, multihash, ownership, old_copy }` | `repository` is the checkout's folder name. A source in a private repository moved into a public one names `path_multihash`, the BLAKE3 identity of its path, instead of `path`: a checkout of that repository finds the path by it, and the path is never published. A source a readable checkout does not hold at that commit is refused; one whose checkout is not here is deferred. `old_copy` is `"same-file"` for a change in place, else `{ deleted_by }`: after that date, or once the contract is `VERIFIED`, the old path still on its repository's main line is refused. `baseline.commit` is the commit here whose bytes of the target equal the source. |
| `NO_PRIOR_OWNER` | `{ job, sources: [], distinct_from: [{ capability \| repository + path, why }], proof: { search: { phrasings, capability_rows, code_patterns, repositories: [{ repository, commit }] } } }` | Every code pattern shares a word with the job phrasings. The judge greps each required repository's main line and runs the capability search again; every file and near row found is named in `distinct_from` with why it is a different job, or the claim is refused. A path ending in `/` names a folder. |
| Feature rules | `ports/feature-files.json`: `{ schema: "port-contracts/feature-files", since, feature_files: [{ matches, ignore?, added?, grown_lines_over? }], contracts_match, contracts_in?, modes, sources_by_repository?, retention_at_least?, old_copy_days_at_most? }` | Carried in the judged repository, or given by the caller. Which repositories a `NO_PRIOR_OWNER` claim must have searched (`--search-repositories`, each found beside the judged repository's main checkout) and the capability search (`--capability-search`, a command that answers a job phrase with its nearest capability rows as JSON) are the caller's, because they describe the machine it runs on; without them both searches are deferred. `contracts_in: { repository, tree? }` reads the contracts from another checkout (its files on disk when no tree is named); `sources_by_repository: false` admits sources named by a path on disk (pictures a visual replica measures). A contract counts at `pre-edit` until it is `VERIFIED`, then at `completion`; its line retention is measured at both. |
| Pixel lock | `{ schema, references, target_screens }` | The measured geometry a visual replica must carry: landmarks, colour samples, typography, spacing, surfaces, controls and element mappings, with minimums. At completion the pixel difference is measured from the pictures and may not exceed three percent. |

## Dependencies

**Depends on:** `tools/content-identity` (BLAKE3), Node's `zlib`, `git` for the repository judge.

**Depended on by:** `tool-rows.json`. The local engine runs the row on the person's computer (`computer` kind) after the person grants `read-a-folder`. `test/every-feature-file-has-a-port-contract.test.mjs` at the root of this repository runs the repository judge wherever the tests run; the check row in the person's check lists (rules-and-their-checks) runs it at commit and push with the full search.
