# keep-goals-and-focus

A person's goals and what the app is focused on. The Home screen that keeps goals, marks the one needle mover and greets the person is in this folder (`web/src/workspace/home-screen.tsx`, moved byte for byte from the web client, which opens it from here as a screen module); with it are its words and the reader that orders goals under the goals they serve.

## Files

| File | Purpose |
|------|---------|
| `home-words.json` | Every word the Home screen showed: greetings, the needle-mover card, the workstreams card, the add-a-goal form, the summary tiles (DATA; the web client's own copy, `web/src/home-words.json`, is what `web/src/workspace/home-screen.tsx` reads) |
| `read-data/pursuit-hierarchy-view.mjs` | Moved from Trillion `src/pursuit-hierarchy-view.mjs` (`moved-from.json`): goals ordered by parent, one row per goal, missing links and cycles kept |
| `read-data/order-goals.mjs` | `orderGoals({ goals })`: the order as one run, with each row's depth and the goal it is shown under (what `tool-rows.json` runs) |
| `web/src/workspace/home-screen.tsx` | Home's parts (`tool:screen-home`, its parts `tool:screen-home-greeting`, `-numbers`, `-needle-mover`, `-workstreams`, `-deciding`, `-waiting`, `-recent`, `-messages`, `-pursuits`, `-suggestions`, and `tool:screen-menu-bar`). Moved byte for byte from the web client (`moved-from.json`); it imports the web shell's files as it was written, and the client build answers those imports with the shell's files. Its description in the client's README, kept whole: Home's parts. Home itself is an arrangement of screens (its row's `surface_input.arrangement`, drawn by `screen-own-arrangement.ts` like any arranged screen, kept per person at `screen-arrangement-of::trillion.home`); `mountHomeCard` (the `home-card` entry) draws one part (its row's `surface_input.card`) and every part on the page draws from one shared read of Home's answers; Home placed inside its own arrangement draws its starting arrangement again as its own place (`screen-own-arrangement.ts`); `mountHomeScreen` (Home drawn bare, reached only twice inside itself) shows Home's greeting. Its parts: greeting with the message box and the next step, stat cards, the needle-mover spotlight (the goal marked `needle_mover`; with none marked, `likelyNeedleMover` guesses the goal with the most goals under it and offers "Make it the one"; with no goal under another, "Have my AI pick", the queue job `pick-needle-mover`), "What your AIs are working on" (`workstreamsCard`, the part `trillion.home.workstreams`: open jobs (the open run of the agent-handoff order through the records door, `home-records.json`) grouped under the job each started from, one line each, stuck first, in the sections of `parts/screen-look/show/work-state-looks.json`), the goals list with "Add a goal" (the shared hover form, fields from `src/home-words.json` `add_pursuit`) and "Make this my needle mover" on each other goal, both saved as pursuit records through `records-door.ts` (a change reads the goal as kept now and writes it back whole with the changed field). |
| `show/home-card-mount.tsx` | The module entry the part rows name: `mount` is `mountHomeCard`, which draws the part named by the row's `card` input. Every part opens from this one file, so they share one bundle and one read. |
| `show/home-mount.tsx` | The module entry of Home drawn bare (`tool:screen-home`, `tool:screen-menu-bar`): `mount` is `mountHomeScreen`; the page draws Home as an arrangement of its parts, so only Home inside itself reaches it. |
| `moved-from.json` | Where `pursuit-hierarchy-view.mjs` came from and the identity of its bytes |
| `tool-rows.json` | The row `tool:order-my-goals-under-the-goals-they-serve`, with a sample run that shows two goals under the one they serve |
| `README.md` | This file |
