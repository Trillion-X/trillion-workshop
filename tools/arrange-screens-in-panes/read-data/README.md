# screen-arrangement read-data

Pure decoders for screen-arrangement package inputs.

## Files

| Path | Purpose |
|---|---|
| `layout-types.ts` | Canonical generic layout state model shared by browser and shell mounts. A `SplitNode` carries `sizes` plus `sizeUnit?: 'share' \| 'px'` (`SplitSizeUnit`): absent/`share` = fractions that fill the split (every layout saved before pane sizes), `px` = each child's own zoom-independent width or height, so the split is the sum of its panes and scrolls; a px length of 0 draws the child at its content's own length (the furthest `[data-fits-content]` inside it). `stackBelow?: number` on a row: on a stage narrower than that many pixels the row is drawn as a stack of its panes, each at its own height (`across`) or its content's. `closeOnOutsidePress` names the floating windows a press outside closes (a side map: the compiled slot keeps unknown top-level fields, not unknown window fields). `focusReturnsTo` maps a floating window to the pane focused when it opened (also a side map). |
| `arrangement-history.ts` | Stores bounded whole-screen arrangement snapshots at the shared layout commit road, with resize coalescing, undo/redo, direct restore, and persisted-shape validation; caps history at 40 entries and 256 KiB. Tab content/title and selection changes alone do not add history rows. |
| `split-tree-operations.ts` | Pure whole-tree operations for the imperative split workspace: `addContainerAtEdge`, `addContainerBeside` (a new pane splitting a pane takes the person's `new_pane_share_percent`; in a same-direction pixel split the newcomer joins as a sibling at its neighbour's size), `removeContainer` (pixel panes keep their sizes), `swapContainers`, `moveContainer`, `sizeSplitInPixels(root, path, sizesPx)` (records a resize as pixel sizes; mismatched or non-positive sizes change nothing). |
| `pane-sizes.ts` | `PaneSizes` (the person's pane settings: drag minimum, screen layout size, cut fade, new-pane share, snapping), `PANE_SIZES_PREFERENCE` (the workspace preference key), `DEFAULT_PANE_SIZES` and `PANE_SIZE_SECTIONS` from `../pane-sizes.json`, `readPaneSizes(own)` (type-checked merge over the defaults), `paneSizesNow()` / `setPaneSizesNow(sizes)` (the current settings for code outside React), `snapPanePx(requestedPx, stagePx, sizes) → {px, snapped}` (the nearest snap mark within reach, the one place an edge snaps, used by the arranger and the Panes preview), `arrowPanePx(currentPx, stagePx, direction, big, sizes)` (where an arrow key moves a pane edge: the next snap mark that way while snapping is on, else `arrow_step_px`, `arrow_big_step_px` with Shift). The settings also hold `added_pane_width_px` / `added_pane_height_px` (a pane added beside or below). |
| `tab-bar-placement.ts` | `TAB_BAR_PLACEMENT_DEFAULT`, `readTabBarPlacement`, `writeTabBarPlacement`, `normalizeTabBarPlacement`: each container's tab bar placement in `LayoutState.tabBarPlacement`, stored as the shared ui `DockablePlacementState`. Absent = top and shown. `TAB_BAR_VIEWS` (DATA rows: Tabs draws each tab in the sidebar's pane-tab row look, List in its plain list rows; a new view is one row), `readTabBarView`, `writeTabBarView`, `normalizeTabBarView`: each container's chosen view in `LayoutState.tabBarView`. Absent = Tabs. |
| `read-screen-arrangement.ts` | Decodes the active direct JSON `layout-state` input, reads legacy RTBL rows only for one-way migration from older logs, and normalizes the result into `LayoutState`. `usableLayerId(layers, activeLayerId, activeLayouts)` names the drawn layer that takes clicks and keys: the chosen one while it holds work, otherwise the topmost layer holding work (also when the remembered layer is no longer drawn), so some layer always answers. `normalizeLayoutState` keeps `closeOnOutsidePress` for windows that exist, and `focusReturnsTo` between panes that exist. `saveLayoutState(state, publication, persistence, expectedIdentity?)` answers `{ refused, identity }`: `refused` when the store kept nothing because the copy was older, `identity` what the store keeps after a write. `arrangement-words.json` holds the words the arrangement says about a refused save. |
| `read-layout-presets.ts` | Reads saved layout preset rows. |
| `read-tab-collections.ts` | `readNewTabCollections(reply) → {presets}` folds saved layouts from one `group.load-graph` reply over the layout-presets index (`LAYOUT_PRESET_INDEX_REF`, read by `do-work/switch-saved-layout.ts`); `surfaceIdsInList(list)` walks a sidebar list tree (`SurfaceCollection`) for every surface id at any depth; `listsPresentHere(lists, catalogIds)` keeps the lists this app can open, plus empty ones only when the person made them (`listMadeByPerson`). Lists themselves are read by the sidebar's `useSurfaceCollections`, never decoded here. |
| `read-published-records.ts` | Re-exports the shared `ui/show/placeable-surface-intent` published-record and placeable-surface decoders, including package-set record wrapper support, then adds screen-arrangement-only discovered-address helpers. |
| `read-projected-rows.ts` | Shared row decoder for package inputs that are still declared as row projections. |
| `read-initial-arrangement.ts` | Builds caller-provided initial arrangement state. |
| `layout-library.ts` | `LAYOUT_LIBRARY`: the layouts a person's AIs make kept as a kept library of the group part (`parts/group/read-data/kept-library.ts`), configured by `../layout-library.json`: their categories and Recent. Read the same way by src/layouts.mjs (through `src/kept-libraries.mjs`) and the Layouts menu (`show/LayoutPicker.tsx`). |
| `starter-layouts.ts` | `readStarterLayouts(raw)` decodes the host's starter DATA (`{id, name, icon?, arrangement}`, where an arrangement node is `{kind:'pane', surfaces, show?}` or `{kind:'split', dir, sizes?, unit?: 'px', keep?: true, across?, stack?, children}`: relative sizes become shares, a pixel size of 0 fits its content, `stack` is the row's `stackBelow`, pixel sizes stay each pane's own length with `keep` keeping them exactly, `across` is each pane's own height in a row or width in a stack or null); `starterLayoutState(starter, surfaces)` builds its LayoutState from the offered surfaces, leaving out panes with none, or null when nothing is offered; `starterArrangementOf(state)` is the way back, the tiled tree of a LayoutState as the same starter shape (each pane's surfaces in tab order, `show` when the showing one is not first, pixel sizes as whole pixels with `unit: 'px'` and `keep`, own cross lengths as `across`, empty panes and one-child splits folded away; a tab whose screen kept something of its own, `metadata.kept`, comes back as `{id, input: {kept}}`), published for AIs by `show/publish-shown-arrangement.tsx`. |
| `place-tab-in-overlay.ts` | Pure composition for surface DATA `open_placement: {layer: 'overlay'}`: `placeTabInOverlay(state, tab, {size?, chrome?}, viewport)` adds one container, one focused overlay box (fitted to the viewport, stepped away from open windows) and that container's own `regionChrome`; `dockTargetContainerId(state, from)` names the first tiled pane a floating window's tab docks into; `removeOverlayWindow(state, id, dockInto?)` closes the window, or docks its tabs into that pane and focuses it. A placement may also give `anchor` (where the window's centre sits, as fractions of the screen; the window is kept on screen), `looks` (visual layer stacks written on the window and on its backdrop through `overlayWindowRegions`) and `closesOnOutside`; `removeOverlayWindow` takes all of them away with the window. A new window remembers the pane that was focused (`focusReturnsTo`), and closing it focuses that pane again. `withoutPassingWindows(saved)` is a saved arrangement as a newly opened page shows it: every window a press outside closes is removed, so it never covers the screen a new address asks for. |
| `region-address.ts` | The one address of every region a look or menu can attach to (`surfaceRegion`, `containerRegion`, `tabRegion`, `backdropRegion`: the whole screen behind one floating window), and `regionAddressKey`, the key `LayoutState.visualLayerStacks` is held by. `overlayWindowRegions(id)` names a floating window's own region and its backdrop. |
| `chrome-visibility.ts` | Resolves chrome-zone visibility maps. |
| `region-chrome.ts` | A region's effective chrome (the arrangement map overlaid with the region's own) and `regionZoneVisible`, the one answer every zone asks: the map and the person's show rules, each zone being the control `zoneControl(zone)` = `arrangement.<zone>` (declared in ../part.json `controls`); immersive toggling. |
| `target-reply-envelope.ts` | The one place that knows an engine reply arrives WRAPPED. `sendRequestToBitfieldTarget` returns `{ payload: Uint8Array }`, so a caller reading fields straight off it sees every field as `undefined`. `insideTargetReplyEnvelope(value)` unwraps to the bytes and passes anything else through, so it is safe to apply twice. The byte test is `ArrayBuffer.isView` plus a one-byte element size rather than `instanceof Uint8Array`, which is realm-sensitive and fails on bytes that crossed a module, worker or host boundary. Exists because this rule was implemented once in `ask-screen-arrangement.ts` and missing in the two composition callers, where it cost the apply entirely. |
| `worker-console-arrangement.ts` | `buildWorkerConsoleLayout(tabs, subject)` (`WorkerConsoleTabSpec`): one pane whose tabs come from DATA, each tab's `surfaceInput` merged with the subject it is scoped to; malformed tabs leave an empty pane. Used by `show/mount-worker-console.tsx`. |
| `build-companion-overlay-arrangement.ts` | `buildCompanionOverlayArrangement(host, companions)`: a LayoutState with the host surface as the full-screen base and each headless companion surface mounted in a minimal overlay box on top, so the companions' on-mount effects run; normalized through `normalizeLayoutState`. |

## Boundary

The active `layout-state` input is direct whole-payload JSON at `["current-item", "published-record"]` under the canonical `screen-arrangement-layout-state` label. Older logs may still expose legacy property-row arrays or published-record row arrays; this folder may read those rows once to migrate them forward into the canonical JSON record, but it does not keep the RTBL shape active after migration.

The active placeable-surface input is owned by the caller through `placeableSurfaceListAddressLabel`. The decoder accepts raw surface arrays and package-set record wrappers with a `records` array, then emits the same generic `PlaceableSurfaceRecord` model for arrangement controls. Screen arrangement does not choose a default app catalog and does not special-case product names.

The older row/table inputs remain as `selected_payload` package descriptors.
They are resolved from log-owned current state when a screen requests them, and
they are not static entry-scope seed values. That keeps compatibility reads
available without making a stale table header block module import.
