# Screen Arrangement Show

Browser components for arranging generic tabs and package material surfaces.

`ArrangedContents` supplies caller-owned live controls to the same arrangement engine, catalog and account layout persistence used by screens. `embedded-surface-content` resolves exact catalog IDs inside one provider and leaves unknown IDs to normal package/target resolution. It changes no record or action ownership. `EmbeddedScreenArrangement` accepts a supplied catalog and `sizing="content"` for inline arrangements whose height follows their drawn panes; whole-screen embeddings retain fill sizing. Local contents are nested arrangements, including across separate React roots. Conditional contents stay in the catalog and collapse while absent so their saved placement is retained. Screen Look owns the spacing and appearance.

## Rules

- Screen arrangement owns placement, focus, tab groups, and ephemeral arrangement interaction state.
- The top-level mount and `LayoutEngine` import `screen-arrangement-context` through the same package alias so the provider and consumers share one React context singleton after bundling.
- Surface-open authority is owner-provided data. `LayoutEngine` reads no browser address: the host opens the screen its page address names (Trillion's `src/workspace/main.tsx` through `src/workspace/addresses.mjs`, the same resolution its Worker answers the address with), so one owner turns an address into an open. It does not route-match product names and does not choose a default placeable-surface list address. The top-level mount receives its list address through component props; embedded callers pass the same contract through `EmbeddedScreenArrangement`.
- It does not inspect file types or choose viewer packages. Browser/OS drops enter through the generic subjectRef path.
- The top-level mount reads and writes the same direct whole-payload `layout-state` JSON record through the canonical `valueAddressLabel: "screen-arrangement-layout-state"` and the package input descriptor's default current-state address family. The old `layout-state` RTBL label is read only as one-way migration evidence for older logs.
- `LayoutEngine` reads the `published-records` input, but screen-arrangement's OWN input descriptor repoints `published-records` to a scoped `record_from_matching_records` json_array sink (`screen-reply-provider-feed`, matching `payload.kind == "reply-template"`), NOT the 34.7MB global aggregate. The aggregate shares the `[current-item,published-record]` path with hot-write layout-state, so every new-tab write invalidated it and re-delivered 34.7MB — the "empty tab takes dozens of seconds" symptom. A layout-state write is not a reply-template, so the scoped sink emits NOOP and this subscription never re-fires on tab churn. The input NAME is kept as `published-records` (not a renamed input) so the 7 packages that bundle this component via `EmbeddedScreenArrangement` (connector-room, content-production, investment-command, media-composition, poker-table, record-audio, record-video) resolve their OWN `published-records` declaration and are not forced to declare a renamed input. `WorkspaceShell` also reads `published-records`, resolved by the bundling embedder's own declaration (it only mounts inside embedders).
- Container chrome, empty tabs, and reply materialization receive decoded records/surfaces as props instead of opening nested data scopes.
- Embedded callers provide `placeableSurfaceListAddressLabel` when they want placeable surfaces. Screen arrangement still decodes generic layout state; the caller owns whether a saved layout is compatible with that caller's required workspace shape.
- Drawing: screen-arrangement owns SPACE RESOLUTION only (`mark-targets.ts` — which addressed space is under the pointer, and how client pixels map into its frame). Ink physics, tools, session, and the single input layer are owned by `packages/addressed-marks`. `LayoutEngine` mounts `MarkSessionProvider`, the world/frame display overlays, `MarkInputLayer` (with this package's resolver), and `MarkToolbar`; the page's own arrangement (`ownsScreen`) also portals the whole-screen ink over the window, and while the session's area is `WHOLE_SCREEN_AREA` the input layer and toolbar cover the window instead (`ArrangementMarkLayers`, exported for its browser test). The pane ⋯ popover says drawing in words: Draw on this pane, Draw on the whole screen, Hide drawings (`DRAW_ROWS` in `ContainerHeader.tsx`). Per-tab `AddressedMarkOverlay`s in `ContainerHost` are display-only.
- The screen-arrangement entry declares its addressed-marks read scope as data in `../entry-read-scope-packages.json` — required for mark records to load inside this entry.
- Header and saved-layout chevrons rotate with the shared 200ms eased disclosure timing so menu open/close motion stays legible without jitter.
