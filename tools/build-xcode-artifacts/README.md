# Build an Xcode app artifact

`build/build-an-xcode-artifact.mjs` runs an existing, approved `.xcodeproj` on an Xcode worker. It knows no app identity, Swift entry point, entitlement, signer, or publication policy. The caller chooses the physical project, scheme, configuration, destination, expected app bundle name, and a fresh physical work folder. The caller also bounds the build's jobs and timeout. The caller is responsible for pinning the project and build inputs and authorizing its build scripts.

Both entry points require the caller's verified heavy-work admission before creating output. Xcode runs under the shared process owner with inherited admission, a time limit and a bounded output stream; the adapter cannot acquire another slot if the claim is lost. Both entry points request no provisioning updates and disable Xcode distribution signing and automatic package updates. They refuse existing work folders and check the expected physical app bundle before returning. Its own `Info.plist` must name a physical, executable file with a Mach-O header. This checks the bundle's structure, not its signature or ability to launch. An error may leave this attempt's own outputs for diagnosis without a receipt.

- `buildAnXcodeArtifact(request)` returns `state: 'built'` and the app in the private products folder.
- `archiveAnXcodeArtifact(request)` returns `state: 'archived'`, the private `.xcarchive` path and its app in `Products/Applications`. The project decides which products it embeds. An unsigned archive is not an exported or signed distribution package.

The same module can run as a process under the caller's existing heavy-work admission. Supply one UTF-8 JSON object (at most 16 KiB) on standard input, with the existing request fields and `operation: "build"` or `operation: "archive"`. It takes no request arguments. Success writes one artifact receipt; refusal exits nonzero without a receipt. No signing, installation, or publishing operation is accepted.

Neither entry point attests to source provenance, exports, signs for distribution, installs, or publishes. No app or tool is registered by this internal module. `migration/build-the-mac-app.sh` is a retired source record of the former combined release; it refuses execution and is not a published entry point. New callers pass a project and build inputs to the generic builder, then hand its artifact to the separately configured signing and install owners. Do not treat a timeout as proof that all Xcode work stopped. On Xcode 26.6 the real fixture received no artifact receipt but its already-running script phase outlived the owned command. Production adoption needs cancellation or verified isolation of those workers as well as the command.

`test/build-an-xcode-artifact.test.mjs` checks input and output ownership. On a provisioned Mac, `PROVE_XCODE_ARTIFACTS=1` builds macOS and iPhone Simulator projects and archives a device iPhone project with a Watch app. The fixtures read bundle identifiers and Mach-O executables, and use no Apple account, simulator launch, or publication action.
