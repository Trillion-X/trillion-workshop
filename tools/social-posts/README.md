# tools/social-posts/

The person's posts, as their own `post` records: drafted, checked for each place they are going, approved exactly as
reviewed, and set to go at their time. The post and connection tools keep nothing: the person's AI reads the records they
need from a store and hands them in as `records` (`[{ id, type, value }]`), and a change to a post comes back as `keep`
(the whole row), for the AI to store. Only the send reads the post and the connection itself, through the run's records
door (read only), because the person's wake runs it at the post's time with no one to hand them in; it too answers the
post as it ends under `keep`. The snippet and thread-summary rows that only kept, found or removed records are retired into the recipes `workflow:keep-the-persons-snippets` and `workflow:keep-conversation-summaries` (tools/workflows/recipes, each proved on PGlite and a JSON folder); `tool:use-a-snippet` and `tool:read-a-thread-summary` stay as computation over the record handed in. The places are rows (`read-data/post-places.json`); the person's accounts are their own `connection`
records, each naming its connection id, the handle the engine reads that account's held values by. No value a place
signs a request with is ever in a record, a row or this code.

Reaching a place is one tool, not one per place: `tool:send-a-post` and `tool:check-a-connection` take `place` (a place
row's slug) and the engine merges that place's variant over the row's `invoke` (`invoke.by_input`) before anything runs,
so each run is handed only its place's connection kind, held fields and token renewal. The variants are made from the
place rows by `read-data/place-variants.mjs` and a test holds the tool rows to them; a new place is a row. The two
YouTube reads (`tool:list-my-youtube-videos`, `tool:read-youtube-comments`) stay as http rows: they ask YouTube's own
wire (an uploads playlist id, comment threads of one video, a page token) and no second place answers those questions,
and `tools/pull-from-connected-accounts` mounts a vendor-named secret with no token renewal, which a Google access token
that expires hourly needs. Adding a place that answers them is a variant of these rows, not a new tool.

Approval is owned by `tool:approve-a-post` in this package's rows. It requires the complete reviewed snapshot and the
post handed in as a record, and answers the approved post under `keep`. `approved_by` is attribution supplied by the caller; it does not claim
that a person saw or pressed a page. The old native adapter and its historical page-only test are held under
`held-source/`: they wrapped the retired EEAF/HTTP lifecycle, whose imports are absent here, and their page-only
approval rule was rejected. The historical test path remains runnable and imports the current common-owner regression.
The existing keeper receipt in `tools/keep-and-wake-ai-sessions-on-this-computer/moved-from.json` records the exact
Trillion source and held bytes at the original bulk-move commit. The live Trillion owner has since changed; this held
adapter is historical evidence, not a second implementation of the current owner.

## Tools

| Tool | What it does | Records |
|------|--------------|---------|
| `tool:list-post-destinations` | The person's accounts a post can go to, each ready or not and why, and each place they have no account for yet | `connection` records handed in |
| `tool:draft-a-post` | Works out a draft: words, file, destinations, link, time; answers the post to keep under `keep`; changing an approved or scheduled post makes it a draft again. Nothing is posted or stored | `post` and `connection` records handed in |
| `tool:check-a-post` | Whether the post is ready for each place: what each will refuse, and what could not be checked here | `post` and `connection` records handed in |
| `tool:approve-a-post` | Approves only with the complete `approval_values` snapshot from review; changed values are refused. The approved post comes back under `keep`. | `post` record handed in |
| `tool:publish-a-post-now` | Queues an approved post for the current time through the existing post wake and each destination's send row. It returns `scheduled` until those rows record their outcomes; an unknown outcome is not retried automatically. The queued post comes back under `keep`. | `post` and `connection` records handed in |
| `tool:set-a-post-to-go-at-its-time` | An approved post with a time still ahead, ready for every place, becomes `scheduled`. The scheduled post comes back under `keep`. Nothing is sent now | `post` and `connection` records handed in |
| `tool:take-back-a-post` | A scheduled post nothing was sent for becomes a draft again, so its time sends nothing. The draft comes back under `keep` | `post` record handed in |
| `tool:check-a-connection` | Asks a place which account one of the person's connections (`account_id`) signs in as, for the `place` given (the slug of a place row that declares a `check`: youtube, instagram, threads or facebook), with its held value placed only as the request leaves and renewed before it lapses (the place row's `refresh`). Answers what the place answers: id and username or name, and for YouTube the channel id, title and uploads playlist id. Posts nothing | none (http, one variant per place) |
| `tool:list-my-youtube-videos` | Lists the videos of the channel a YouTube connection signs in as, from its uploads playlist (`playlist_id` from the check), with each video's privacy status, unlisted and private included when the sign-in can read the channel. Posts nothing | none (http) |
| `tool:read-youtube-comments` | Reads the top-level comment threads of one video (`video_id`, run once per video) through a YouTube connection (`account_id`), 100 to a page: text, like count, publish time, reply count and the commenter's channel id only (no display name). Posts, rates and moderates nothing | none (http) |
| `tool:read-post-calendar` | The posts between two times, earliest first, each with whether it can still move, and the drafts and approved posts with no time yet | `post` records handed in |
| `tool:see-how-each-post-did` | How each place a post was published to did: that place's own counts (handed in), the visitors its link brought and what they bought (handed in, in tool:break-down-visits-and-sales' shape), joined by exact identity only | `post` records handed in |
| `tool:send-a-post` | Sends an approved post whose time has come to one destination (`place`, the slug of a place row: youtube, tiktok, instagram, facebook, instagram-facebook, threads, linkedin, substack, x, beehiiv or ghost, and `account_id`, an account of that place's connection kind; a place that is not the account's is refused before anything is read or sent) and keeps where it went. The engine hands the run only that account's held values; each reaches only the place's hosts as the request leaves. A destination the post carries as not known is never sent again by itself, and each send hands the place an idempotency key made from the post, the account and the attempt, and the post as it ends comes back under `keep`. A post with a file needs `media_url`, an address the caller made of that file where the person keeps it; the place gets (media_from in its place row) that address (address), the bytes streamed from it (stream), or the bytes as one piece (whole); no address, or an address that answers the file is gone, is refused before anything leaves. The post and its connection are handed in as `records`; it is told the post's `armed_at` by its timed run (`workflow:send-each-post-at-its-time`) and sends nothing once the post no longer carries it. It posts publicly: run it only with the person's yes for that post | none: the rows it reads are handed in, and what it keeps comes back under `keep` |
| (retired) `tool:send-each-post-at-its-time` | Retired into `workflow:send-each-post-at-its-time` (tools/workflows recipes and kits): its minute wake reads the due posts with run-sql in the person's own database and hands each due destination to `tool:send-a-post`, then writes each post back as its answer came. | none: the wake reads through run-sql, not a records door |
| `tool:use-a-snippet` | A snippet's words with the blanks given filled; each blank given no value is left as written and named back in `left_blank`. Fills and counts nothing; never rewrites the words | `snippet` record handed in |
| `tool:read-a-thread-summary` | The summary kept of one conversation, and how many of `message_times` (the conversation's newest message times, handed in) come after what it covers: `newer_messages`, `stale` | `thread-summary` record handed in |

## Key Types / Functions

| Name | Shape | Role |
|------|-------|------|
| Post record | `{ post_id, status, caption, media?, caption_by_platform, settings_by_platform, destinations: [connection id], link?, scheduled_for?, time_zone?, source?, format_id?, reaches?, deliveries?, created_at, updated_at, approved_at?, armed_at? }` | One post; status is draft, approved, scheduled, posted, failed or partial. |
| Connection record | id `connection:<connection id, URL-encoded>`, value `{ connection_id, vendor, service?, account_label?, plain: { field: text }, held: [field], can_send? }` | One of the person's accounts: its readable fields, and the names (never the values) of the fields its vault holds. |
| Place row | `{ id, platform, label, adapter, connection_vendor, options, account, hosts, media_from, default_settings, format, refresh?, check? }` | Where a post can go and what it takes. |
| Observation | `{ post_id, account_id, metrics: { name: number }, observed_at? }` or `{ platform_post_id, account_id?, metrics }` | One place's own counts for one post, read with that place's tools. |
| Result row | `{ post_id, account_id, title, platform_post_id, url, metrics, observed_at, brought?: { visits?, conversions?, value? }, evidence }` | What one published place did; `brought` holds only what was counted. |
| Snippet record | id `snippet:<saved at>:<10 hex>`, type `snippet`, value `{ snippet_id, title, text, tags, set_at, uses, used_at? }` | Words the person sends again and again; `{name}` in `text` is a blank. |
| Thread summary record | id `thread-summary:<app or ->:<conversation_id>`, type `thread-summary`, value `{ summary_id, app, conversation_id, summary, through_message_id, through_at, set_at }` | An AI's summary of one conversation and the message it covers through. |
