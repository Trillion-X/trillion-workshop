# tools/carry-a-computer-to-a-meeting-point/

Carries a computer to a meeting point: a program the computer starts that dials out to a public host, so a computer behind a router is reached with no inbound port, and the engine on it carries no bytes between computers itself. Which program, with which files and arguments, is a **way row** (`read-data/ways.json`); one runner starts whatever a row names. It replaces `tools/keep-a-door-tunnel-open`, which could only run one SSH forward and only under launchd.

A way row is `{ id, transport_kind, relay_host_ref, client, params, order, requires_awake, install }`. `client` is the program (a pinned download with its BLAKE3, or a command already on the computer, chosen by what the computer is), the files it is given in a private folder that is removed when it ends, and its arguments. `server` is the same for the meeting point's host: ordered steps (a file, or a command) with an `each` that repeats per carried computer. Four rows ship, in order: `ssh-certificate` (one `carry` user at the meeting point, which admits a certificate the meeting point's engine signed and lets it listen on its own port alone, so nothing is written per computer and no one can take another person's port), `frp` (0.72.0 of 2026-11-04, Apache-2.0, native builds for Apple silicon, linux x64, arm64 and arm, and Windows, each pinned by BLAKE3; frps takes one token for the meeting point, and the host's `allowPorts` list holds each computer to its own port, so a token holder could ask for another listed computer's port), `rathole` (0.5.0 of 2023-10-01, the project's newest release, Apache-2.0; a token per computer; no Apple-silicon build, so such a Mac runs the x86_64 build under Rosetta) and `ssh-reverse-forward` (the host key pinned, a service user that may listen on one loopback port and do nothing else). A person's own way is a row of the same shape; no code names a program, an operating system or a host.

The port a computer listens on at the meeting point is a stable hash of its id: BLAKE3 of `salt:id`, its first four bytes, modulo the width of the range in `read-data/ports.json`. It is derived, never listed; two computers that hash to one port on a host are refused, and one is given a `salt`. A caller that needs the port (the lane that builds `remote-mcp` sources) calls `portFor(computer_id)` or reads it from the install's answer.

The program is kept running by the init row for the computer's kind (`tools/start-a-computer/read-data/init-rows.json`, installed by `tools/start-a-computer/do-work/install-init.mjs`): launchd, systemd, a Windows startup task or Quadlet. `install` copies the files the carrier needs (`read-data/carrier-files.json`) into the state folder, because the engine keeps only its current and previous Workshop copies, and the init row points at that stable copy.

## Running it

On the carried computer: `node do-work/carry-a-computer.mjs install CONFIG_FILE STATE_FOLDER`, with a configuration `{ label, way, relay_host, computer_id, local_port, credential_command?, values?, init_values?, announce?, state? }`. With a `credential_command` (the Mac: the key is on descriptor 3 of the command) the credential is that command's answer. With none, the carrier keeps its own key in `<state>/key` (folder 0700, files 0600): the way's `key.make` runs there on the first start, the private half is the credential and the public half is announced as `values.public_key` unless the configuration gives one, and every later start reads the same key back. `announce` `{ argv, every_seconds }` is the command that tells the meeting point whose computer is at this port (with `{remote_port}` filled): run at once and every `every_seconds` while the carrier runs, and never after it ends, so the meeting point's announcement lasts only while the computer is carried (trillion-rust src/native_entry/meeting.rs). An `announce` with `gives` (`{ value name: answer field }`) is asked before the client starts, and the client is started only once it answered: the `ssh-certificate` row's meeting point answers the port it derives for the signed-in person's computer and a short-lived certificate for the carrier's own key that may listen on that port alone (`gives: { remote_port: "port", certificate: "certificate" }`, with the public key in the config's `values`). The answer sends no calls anywhere: the carrier says `{carried}` true only once the client has held its port for `settle_seconds` (default 3) and at each renewal, a refused renewal ends the client, and a failed try moves to another `{salt}`, so a computer is never announced at a port someone else listens on. `credential_command` is the vault command, by the held value's name, that writes the value only on its descriptor 3; it is never in an argument or a file the configuration names. `remove` undoes it. On the host, `tool:carry-a-computer-to-a-meeting-point` says what to run, and `tools/start-a-computer` renders it on a public computer.

## On a Linux server

`on-a-computer/carry-a-computer.service` is the unit a computer row names as its `template` to run this carrier under systemd. Its fields: `description`, `user`, `cli` (the site's command name), `state`, `workshop`, `tool_folder` (this tool's folder, whose own `package.json` and lock name the one package the carrier imports, `@noble/hashes`), `workshop_commit` (a full commit id, fetched from `repository`), `node_bin`, `writable` (the state and Workshop folders, which must exist and belong to `user`), `credentials` (the announcement's credential, handed to it in the variable its `env` names), and `settings_file` (the configuration, written by the row's `files`). The unit fetches the pinned commit into `workshop`, runs `npm ci` in `tool_folder` from this tool's own `package-lock.json` only when that lock changed (so a server installs one package, never the whole Workshop's), links the Workshop's `use-your-tools-from-a-shell/do-work/command.mjs` at `<state>/bin/<cli>`, and runs `serve` with no `credential_command`, so the carrier keeps its own key in `<state>/key`. The link matters: the command names its site, and so the variable it reads its key from, after the name it runs as. `HOME` is the state folder, where the command keeps its keeper socket. The announcement is `node <state>/bin/<cli> op --origin <site> --address @meeting computers:announce …`.
