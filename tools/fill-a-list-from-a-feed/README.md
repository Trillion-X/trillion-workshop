A one-to-one port of old trillion `src/list-feed.mjs`. The canonical feed reader remains `watch-my-sources`, declared selectors remain `ui`. The person's list and its rows are given to the run in `stored.records` (the list's record and the rows of its kind, read by the caller from the person's own store), and the run answers what it made in `keep` for the caller to keep. The run reads and writes no store.

`tool:fill-a-list-from-a-feed` runs `fillAListFromFeed(input)` through `do-work/run-given.mjs`, preserving JSON/RSS/Atom intake, stable collision-safe row ids, bounded writes, fixed values, prefixes, person edits, opt-in updates, media capture (kept as `files` in keep), and run stamps (kept on the stamped row). Each kept row carries `expected`, the record as the run was given it, so the caller's write is conditional. The function API also preserves the shared-library algorithm with an explicitly supplied admitted `library.add` owner. The installed list row does not claim that a shared-library host is connected.

The source-first history was committed before adaptation at `4097cf388bed69c02c50ad396d667d424ac942da`. Tests run the real fill over given records (`givenLists`), apply each run's keep the way a caller does, and check the rows, files and refusals.
