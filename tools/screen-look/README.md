# Screen Look

`show/anatomy/iso-style.mjs` owns Anatomy materials as well as `ISO_CSS`.
`anatomyMaterialStyle(name, quiet, { lit })` supplies the shared face, top and shade
tokens for SVG geometry. Set `lit: true` when using `solidSvg`'s lit surfaces so
those surfaces keep the chosen material instead of inheriting the base white
highlight. Material choice belongs to the scene; its paint values stay here.
The default and quiet calls retain their existing output.

`show/surfaces.css` grounds the shared RecordViews toolbar from its first paint, including translucent looks, so
CSS pinning never waits for an observer before covering scrolling words. Reference: 21st.dev Toolbar 19516 (surface
anatomy only, no copied code); proof: `test/record-views-toolbar-paint.test.mjs`.

`show/public-share.css` styles generic shared-link collections, including the bounded prose cover used when a card already carries text. When a focused item contains a reading column, the share's header, related cards and footer still span the page. File bytes remain the share owner's concern; this appearance layer never fetches them.

`show/candidate-field.css` supplies the content-first selection field: in-place reading, contextual selection and action controls, single/grid presentation, and bounded mobile conversation space. Domain records and requests stay in the consumer; the shared `ui/show/coss/candidate-field.tsx` consumes the existing MIT Coss primitives and the caller's protected media player.

`show/dockable-panel-style.ts` owns integrated versus detached panel appearance and is explicitly declared as public source. Shared sidebar consumes it without a Documents-specific stylesheet.

`show/editorial-link-card/EditorialLinkCard.module.css` gives the shared public link-card structure its surface, type hierarchy, focus/hover response, responsive sizing, and reduced-motion behavior. Landing-page article links and related-reading links consume the same appearance; their copy and destinations remain page DATA.

`show/beui-activity.css` supplies shared activity-row wrapping and reduced-motion-aware pulse appearance for the licensed BEUI StepRow consumer.

`show/media-review.css` adapts the shared playback/transcript owners for Expansion.

`show/layout-picker.css` draws the Layouts picker's thumbnails and the pane map (parts/screen-arrangement ArrangementNavigator): each pane tile with its dot (the accent dot marks the pane in view), the resize line on a pane boundary, the dashed square where a pane would be added or a dragged pane would land, and the dragged pane following the pointer, every colour a look token.
Transcript text and timestamps retain readable contrast in both themes; inactive
rows stay opaque, while accent borders and backgrounds identify the active segment.
Its editor inspector styling follows the licensed Diffusion Studio 0.200.0
panel-section and control-row anatomy: compact 11px controls, 28px fields,
fine separators, and a clear blue selected-tab/focus state. `show/diffusion/`
supplies the matching range-control appearance for the exact shared Diffusion
slider; behavior remains in `packages/ui/show/diffusion`.

`show/coss-workspace.css` provides wrapping values, scrollable long cells and row
action spacing for the licensed shared record table. Table behavior remains in ui.
It also gives the shared publishing chooser distinct platform, linked-account,
and supported-format surfaces, with compact count marks and a narrow-pane layout.
It is also the Tailwind compile input, so it defines the workspace `hover` variant: every `hover:` and
`group-hover:` utility matches a resting mouse (where the device can hover) and the chain the last tap landed in
(`data-touch-hover`, set by `ui/show/touch-equivalence`), so a finger reveals what pointing reveals.
Its theme also names the tones the shared Badge speaks in (`status-success`, `status-warning`, `status-error`,
`status-info`, `accent-purple`) from the worn look's own `--color-success`, `--color-warning`, `--color-error`,
`--color-info` and `--accent-purple`, so a toned chip draws with its tinted ground (test/badge-tones-in-workspace.test.mjs).

Success badges read paired `--badge-success-bg` and `--badge-success-text` roles from the palette resolver. It realizes
the existing 65% success tone and 15% tint as concrete RGB/RGBA values after the worn look's authored tokens, so
Tailwind's nested `color-mix()` fallback cannot turn the tint opaque under Dark Reader. Explicit paired-role tokens
remain editable. The existing shared Badge structure and fonts are unchanged; 21st.dev Button
138 was inspected for its paired foreground/background anatomy, with no copied code or replacement component.
An authored text or background role is preserved independently, including color formats the resolver does not
parse; only an absent role receives its derived default. These roles do not change the authored success tone.

Package-owned root look/visual layer for Bitfield Studio.

## Files

`show/schedule-calendar.css` styles the shared hour-lane slot preview, resize handle and non-working-hour shading. `ui/show/hour-grid/HourGrid.tsx` imports it; no calendar records or words live in this appearance file.

`show/text-highlights.css` is how each text mark kind looks (`::highlight(trillion-find)`, `trillion-citation`, `trillion-review`): only a background or underline over the marked words, their own element and colour kept. `ui/show/text-highlights/text-highlights.ts` imports it; the kinds are named in its `text-highlights.json`.

`show/live-composition.css` is the look of the live cut player (`ui/show/selection/LiveCompositionPreview.tsx`): the frame of the chosen shape, the picture layers over it and its playback controls; loaded through `scripts/workspace-looks.json`.

`show/public-app-capability.mjs` styles shared public capability cards and their native action controls. Message areas have room for long text; repeated text entries share responsive input/remove rows, secondary add/remove buttons, field errors and character hints. It inherits the consuming Screen Look's surface, text, border, focus and error tokens; the consuming app supplies only presentation DATA and words.

`show/public-app-editor.css` styles the Sites editor's Layers, Add and Sources side panel. The Sources list reuses the shared search field and presents studied-screen observations with their original links; its 21st.dev button opens the external catalog and does not imply an API connection.

The shared copy button's look is `show/copy-button.css`. Expansion's source-derived additions live in
`show/media-loading.css` and `show/aicss-activity.css`. Behavior and pinned
source/license records are in the matching `ui/show` folders. These are consumed
by Expansion's shared-controls build, not claims of live Trillion convergence.

## Rules

- Root executable source is declared with `source_bytes.address_label` pointing at the live package entry-byte record.
- Integrity metadata may remain metadata, but it must not be selected by the scene projector as code source.
- Visual policy stays package data; the platform shell remains a generic thing-to-put-on-screen runner.
- Runtime Kit package-set folders are not source authority after admission; restore/reseed from this package source into the log.
- The editable look list is the derived `package::screen-look::published-records` feed over `current-item/published-record/screen-look-editable-theme` records, not a hand-maintained UI fallback.
- A device may keep its own look over the account's (Only on this device, in the card grid and the popover). While it does, choices go to this device only and the account's look is never written; turning it off forgets the device's look and the device wears the account's look again. Looks the person saves always go to their account's own looks.
- The card grid previews each look from its resolved surface and accent colours. A choice repaints the page at once (PaintChosenScreenLook) and stays selected after a reload, from the account record or this device's own look.
- Settings uses shared `ui` buttons for selection and edit/create actions, with reduced-motion styling on the preview cards.
- Shared public auth-screen styling lives in screen-look as generic root visual
  CSS. Account-like package sets can provide branded markup and still get the
  same responsive split/mobile card, background wash, form sizing, and Look
  control spacing without duplicating package-local CSS.
- Auth-screen form controls are normalized in screen-look too: labels are grid
  rows, inputs are full-width bordered controls, buttons are full-width
  centered actions, and the mobile Bitfield wordmark is clamped so it does not
  push the sign-in card off-center.
- Account auth copy and brand alignment also live here: the Bitfield wordmark is
  centered in the responsive card, the wide split keeps brand/form composition,
  and the sign-in headline uses a lighter Bitfield-appropriate weight.
- `show/event-invitation/` composes the domain-blind `ui` invitation structure
  with screen-look-owned contrast, typography, borders, action, surface,
  responsive, and reduced-motion roles. Product callers supply only real event
  facts, media, copy, and actions.
- `show/morphing-ribbon/` owns the exact 736×414 background, forest ribbon,
  type pairing, grain, and shadow translated from saved X post
  `2042290581750059141`; its shape and motion behavior come from shared `ui`.
- `show/beautiful-ui-controls.css` owns the MIT BeautifulUI-derived DOM composer,
  choice-list and dialog appearance consumed by Expansion. Full notice is
  `show/BeautifulUI-LICENSE.txt`; source provenance lives in

**Depends on:** `#workspace-records` (the workspace's records: inputs `editable-screen-look-themes`, `own-screen-look-themes`, `current-screen-look`, workspace preferences), `parts/ui` (Button, Switch, Text, Icon, AnchoredOverlay, notifications, Kibo file dropzone, file download), browser storage for a device's own look.

**Depended on by:** `src/workspace/main.tsx` (page surface, and the Screen look page as entry `screen-look`, the screen of tool:screen-looks), `src/looks.mjs` (the looks owner every AI and the Marketplace reach: `read-data/screen-look-record.ts`, `read-data/read-editable-screen-look-themes.ts`, `read-data/resolve-screen-look-palette.js`), `src/workspace/guide-screens.tsx` (the card grid lent to the Account screen), the Mac media workspace (`mount-screen-look-surface`, `mount-screen-look-full-surface`), tests `test/looks.test.mjs`, `test/screen-look-on-this-device.test.mjs`, `test/screen-look-popover.test.mjs`, `test/workspace-input-writes.test.mjs`.

`show/coss-workspace.css` also names the common status tones (`success`, `positive`, `warning`, `attention`, `error`, `danger`, `bad`, `info`, `neutral`, `muted`) as aliases of the record-kind palette (`--record-kind-<tone>`), so a state whose look says one of them draws in a real colour on a map card, a chip or a line instead of falling back to grey.

`read-data/look-scheme.ts` is the pure, JSON-free question "is this look light or dark": `screenLookScheme(variables, groundRole)` reads the look's own ground colour (with `parseColour`, `colourOf`, `contrast`, `toLinear`). `look-over-time.ts` re-exports it and `show/ApplyCurrentScreenLook.tsx` asks it with the plan's ground role; a public share page's script (`src/workspace/share-view.tsx`) imports only this file, so the share bundle carries no look-over-time plan data. `show/chart.css` holds the chart roles (ring centring, phone wrapping of the readings and legend).

`show/timed-text-style.ts` owns the existing caption and transcript word colors, current-word highlights, hover behavior and passage looks. Shared UI `inline-text-action` supplies the interaction; media playback supplies timing and words. No new appearance was introduced.

`colour-ladder.json` + `read-data/colour-ladder.ts` decide what a look does with a value it cannot draw: a colour with a channel out of range, a wrong-length hex, an unknown word, a number past its own bounds, or text that could close a style rule takes the next rung (the default look's colour for that token, then a neutral grey; the nearest bound; the default) instead of failing the look. Saving through `save_look` stays strict and refuses with words; both use the same `isColour`. Proof: `test/colour-ladder.test.ts`.

`theme-inputs.json` + `read-data/theme-from-inputs.ts` make a whole look from three picks (base, accent, contrast 0-100): every colour token is derived in OKLCH from role rows, written as `#rrggbb`, and held to contrast floors by moving ink away from its ground. `save_look` takes `colours: { base, accent, contrast? }`. It builds on `read-data/tint-look.ts` and `tint-rules.json` (the any-tint look owner). Proof: `test/theme-from-inputs.test.ts`.
