# src/workspace/

The signed-in Trillion workspace at `/work`: the shared sidebar, the screen arrangement (tabs, panes, dragging between panes, the pane map) and this app's own screens, built by `scripts/build-workspace.mjs` into content-named files under `/workspace/named/` (the page's script, one file per screen fetched when that screen first opens, the stylesheet and the compiled parts' bytes), named for the Worker by `/workspace/files.json`; the Worker serves them from its static assets and lets a browser keep them for a year (`src/workspace-files.mjs`). The page's own response carries the first answers only for `page_answers_ms` (`src/connecting-without-the-store.json`, about 2.5 s): the ones not settled by then are left out and the page asks for them itself (`api.ts`: an answer the document ended without is asked for, never taken as empty).

## Saved views drawn another way

`lists-screen.tsx` reads a saved view's `display.as` (set by `save_list_view`, kept by `trillion-workshop/tools/keep-lists-of-rows/read-data/saved-view-engine.mjs`) and opens the list drawn as that view when the view is chosen or asked for by address (`?view=<id>`, which is also how a chat card of `read_list_view` is drawn); its `display.settings` reach the view through `RecordViewContext.settings` and are saved back with `saveSettings` (`parts/ui/show/record-views/README.md`). `main.tsx` and `screen-view.tsx` both import `parts/ui/show/chart/offer-chart-view` so the Chart view is offered to every list in the page and in an AI app's chat card; before, neither bundle imported it, so a chart view could not be drawn in either.

`share-view.tsx` also marks the worn look's scheme on `<html data-look-scheme>` (read from the page's own `--bg-primary` through `parts/screen-look/read-data/look-scheme.ts`) before drawing the saved views, so charts and other screen-look styles that key on the scheme follow a dark look on a share page.
