# Progressive document

Renders one caller-authored argument as continuous prose. The opening promise can add its society clause, then the complete opening-to-ending skeleton appears. Ordinary scrolling reads that argument without revealing its details early. The hero marker advances only the main explanation through caller-owned `narrativeDepth`, then returns to the complete short skeleton. It clears local detail choices and keeps the headline at the same position. Colored insertions stay behind their own nearby markers. Ctrl/Command plus wheel or a two-finger pinch changes global detail deliberately. Each later `ProgressivePart` stays in caller order as an inline `span`; a nearby marker button reveals or collapses only that insertion. Per-part choices persist while global depth changes. The keyboard-accessible full-reading link exposes all depths and clears local collapses so the complete document is visible.

`ProgressiveDocument.tsx` composes the shared Coss `Button` for inline markers and one `Reveal` for the complete skeleton. Paragraphs remain normal `<p>` elements, including framework names. Text size does not depend on depth, and ordinary wheel input is left to page scrolling. Modified wheel and touch listeners are attached only to this article. Before inserting content, it records the reader's paragraph and restores that paragraph's viewport position after layout. Retained words within and after the insertion use finite FLIP transforms, preserving natural whitespace and driven by the Screen Look's arrival duration and easing; layout reads use the shared `readLayoutTogether` helper. The first two downward scroll movements expose the society clause and then the complete skeleton; a large jump exposes the skeleton immediately. After that, ordinary scrolling does not open details. There are no paragraph detail triggers or recurring idle frame loops. Reduced motion exposes all text without arrival animation.

The caller's part array is the prose order. To place a depth-2 skeleton sentence around later detail, the caller can keep its opening and continuation as separate depth-2 parts with deeper insertions between them. Adjacent parts with the same kind and depth share one marker; deeper markers become available after preceding insertions open. Hidden parts have no `data-visible` attribute; visible parts carry `data-kind` and `data-min-depth`. Local markers use `aria-expanded` and `aria-controls` for their exact associated insertion group. The opening promise is the page h1. The school name is explained in the prose; no decorative label precedes the headline. The hero marker controls the argument, and the full-reading link remains available to keyboard users.

Named terms use the existing shared outlined Badge, and inline arrows use the shared outlined Button face at the passage’s baseline. Only a named term receives medium weight; a whole content kind is never made bold or italic. The hero control scales with its headline and retains a 44px minimum target.

Appearance belongs to `parts/screen-look/show/progressive-document.css`. Import through `index.ts`; `parts/ui/part.json` declares the public entry and `parts/screen-look/part.json` declares the stylesheet. The screen-look counterpart carries typography, inline marker appearance, spacing, focus treatment and reduced-motion behavior.
