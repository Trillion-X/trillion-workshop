# document-page

The HTML sink for server-sent pages, email bodies and share cards: callers hand words, links and markdown, and only this folder writes tags.

## Files

| File | Purpose |
|---|---|
| `word-marks.json` | The marks `markdownHtml` draws inside plain words with `marks: true`: a bare address (a link), a `#tag` and an `@handle`, each a pattern row; a new kind of mark is a row |
| `document-page-html.mjs` | `documentPageHtml` (a whole readable page with head facts, JSON-LD, header, article, blocks, footer), `documentHeadHtml` / `documentBodyHtml` (the same head facts and readable body for a page whose shell another build wrote, such as a landing drawn in the browser), `emailMessageHtml` (html and text parts of an email, coloured from a caller's palette), `shareCardHtml` (a 1200x630 card a headless browser photographs), `carouselSlideHtml` (one 1080x1350 social carousel slide in the same look), `markdownHtml` / `markdownText` / `markdownBlocks`, `anchorFor`, `safeHref`, `escapeHtml` |

## Key Types / Functions

| Function | Shape | Role |
|---|---|---|
| `documentPageHtml(page)` | `{ lang, theme_attributes, title, description, canonical_url, share_image_url, share_kind, site_name, published_at, modified_at, noindex, alternates[], stylesheets[], icons[], json_ld[], header: {brand, nav, icons, toggle_label}, article: {title, lead, byline, dates[{iso, label}], markdown, toc}, blocks[], footer: {links, columns[{heading, links[{label, href}]}], columns_label, lines} }` -> string | One page. `header` is the site's top navigation from nav DATA (`../site-nav`: links, a features menu with icons and previews, actions), the same navbar the React `SiteNav` draws; `header.icons` maps each row's icon name to its shape rows. `published_at` and `modified_at` are written as `article:published_time` and `article:modified_time`; `article.dates` draws each `{iso, label}` as a `<time>` line under the lead ("Published October 3, 2026", "Updated October 5, 2026"), the caller's own words. A block is `{ id, date: {iso, label}, heading, image: {src, alt, width, height, caption}, diagram, markdown, links[{title, href, detail}], filters: {label, items[{label, href, current, count}]}, cards[{title, href, meta, detail, image: {src, alt, width, height}}], panels[{title, markdown, current}], questions[{question, answer}], action: {label, href}, form: {action, submit_label, note, fields[{name, kind, label, placeholder, required, autocomplete, trap, value}]}, note, tone }`; a page and its blocks draw no small label line above a heading (the context is the heading itself); `id` (or else the heading) names the block's anchor, `date` is written as a `<time>` with its machine date, `date` is `{iso, label, qualifier}` where `iso` may be a day, a month or a year and `qualifier` is the caller's words under the date (e.g. that it was pieced together); each run of `tone: "timeline"` blocks shares one rail: on a wide screen the date keeps its own column and stays in view while its entry scrolls past, a thread fills the rail to the middle of the screen as the reader scrolls and each entry's dot lights when the thread reaches it (the page's only script for it, sent once and only when a page has a rail; with reduced motion or no script the rail is simply full); used by a changelog and a story page, `tone: "callout"` a tinted box, `tone: "split"` the block's picture beside its words on a wide screen. `panels` are titled cards side by side holding markdown (two tools' strengths, two price lists; the `current` one is the page's own side, drawn a step stronger); `questions` each open their own answer (a native disclosure: no script, keyboard and screen reader work, every answer is in the page). The footer's `columns` are lists of links under their own headings (every comparison page, grouped). `diagram` is a layer diagram (`../layer-diagram`: layers of nodes joined by edges, the same picture the React `LayerDiagram` draws), placed after the picture; its look is added only to a page that draws one. `filters` is one scrolling row of pill links that narrow the page (each filtered view is its own address, filtered on the server; the current one carries `aria-current`); `cards` is a grid of picture cards, each one link (picture at the article picture's shape, a short line above the title such as a date or a shelf, the title, a line of detail), and a block holding cards widens to the page's wide measure on a large screen. `action` is the block's one main link, drawn as the page's button (a sign-up or a booking). `article.share` (after the article's body) and a block's `share` (at its end), each `{ url, text, compact? }`, draw the shared share row (`../share-row`: Copy link, X, LinkedIn, the phone's share sheet); its script is added only to a page that draws one |
| `documentHeadHtml(page)` | same `page` -> string | Title, description, robots, canonical, Open Graph, Twitter card, alternates and JSON-LD, to add to a shell another build wrote |
| `documentBodyHtml(page)` | same `page`, plus `hidden_when_scripted` -> string | Header, article, blocks and footer as plain markup; with `hidden_when_scripted` it shows only where no script runs, so crawlers and answer engines read a page the browser draws itself |
| `emailMessageHtml(message)` | `{ preheader, markdown, action: {label, href}, footer_lines[], footer_links[], brand: {name, image}, palette: {ink, accent, muted, paper, line, on_accent} }` -> `{ html, text }` | One email, inline-styled; the text part carries every link address |
| `shareCardHtml(card)` | `{ title, detail, brand, stylesheets[], theme_attributes }` -> string | The share image's page |
| `carouselSlideHtml(slide)` | `{ title, detail, points[], footer, page: {index, count}, brand, stylesheets[], theme_attributes, width = 1080, height = 1350 }` -> string | One carousel slide's page; the footer shows `footer` or `index / count` |
| `markdownHtml(md, { linkClass?, newTab?, links?, breaks?, marks? })` / `markdownText(md)` | string -> string | `breaks` draws each line break inside a paragraph as one (words written for a post or a message); `marks` draws each `word-marks.json` mark in plain words as `<span class="doc-mark" data-mark="<id>">` (a bare address as a link with `data-mark="link"`), never inside a markdown link's label or inline code. Headings, paragraphs, lists (a `[ ]` / `[x]` item draws as a task with its box), quotes (a one-line quote as a pull quote; a quote of several lines or blocks, such as a pasted chat turn, as `doc-quote--held` holding its own paragraphs, lists and code), tables (`| a | b |` with a `|---|` rule line, `:--:` alignments as `data-align`, inside `doc-table-wrap` so a wide table scrolls), fenced code blocks (kept verbatim, escaped), rules (`---`), bold, italic, strikethrough (`~~`), inline code, links, pictures (`![alt](https://...)` as `doc-img`, only for safe addresses), a line ending in two spaces or `\\` as a line break; raw HTML is shown as text; `newTab` opens every link that leaves the page in a new tab with `rel="noopener noreferrer"` (a file shown inside another app, `ui/show/file-preview`); `links: false` draws each link as its words, for a passage inside something that opens as a whole (a file's tile, `ui/show/media-preview` `markdown-snippet`) |

## Invariants

The header's textual brand may opt into `text_style: "wordmark"`. It draws the shared SiteNav wordmark style using Screen Look's display font; an image brand keeps its existing image treatment. Other text styles do not become markup or CSS.

- Every caller value is escaped; a link is written only for `/...`, `#...` or `http(s)://`.
- JSON-LD is `JSON.stringify` with `<` escaped, so no value can close its script element.
- No colour value is written here: pages read theme role tokens (`--ink`, `--thread`, `--grey-strong`, `--grey-soft`, `--surface-base`, `--paper-tint`, `--button-bg`, `--button-text`, `--focus-ring`); emails take a palette the caller read from its theme file.

## Dependencies

**Depends on:** `../server-rendered-page/escape-html.mjs` (`escapeHtml`), `../share-row/share-row-html.mjs` (the share row), `../site-nav/site-nav-look.mjs` (the nav reading, look and open-and-close script), `../layer-diagram/layer-diagram.mjs` (a block's diagram and its look).

**Depended on by:** `ui/show/markdown-block` `MarkdownWords` (every reading surface in the app: file previews, emails, opened records, posts), `dev/trillion-site/worker` (gettrillion.ai articles, the changelog, the story page, email list pages, emails, share images and carousel slides). Tested by `test/document-page.test.mjs`.

Public Sites pages may supply `placements: ["declared-placement-id"]`. The document renderer places the existing public capability runtime hosts at the end of the main content and loads its module once. The installed site must declare each placement and action; no form controls or private records live in the document. Include the shared capability stylesheet with the consuming Screen Look. Invalid ids are refused.
