# ui/show/chart/

One chart family for every Trillion screen: line, area, bar, stacked bars, sparkline, ring (donut) and heat map, and (adapted from Spectrum UI) pie, radial, radar, treemap, ranked bars, composed, candlesticks, histogram, step line and step area, drawn from DATA and crafted past typical chart libraries (scrub by pointer, touch or arrow keys; a tooltip card with every series and how the slot stands against each budget; budget and target lines labelled where they start; hatched "so far" periods; empty, loading and one-reading states; narrow layouts; motion).

## Files

| File | Purpose |
|------|---------|
| `Chart.tsx` | `Chart` (and the pure `slotRows` that lists what a tooltip shows for a slot; role marks list their roles in order with no total): measures its width, lays out the x/y frame (nice ticks, horizontal gridlines, x labels that never collide (band and category labels are thinned to every k-th by `labelStride` when slots are narrow), y labels inside the plot when narrow), draws the mark, the crosshair or column band (on every cartesian mark: a vertical guide, a horizontal guide at the hovered value and a value tag on the axis edge), the volume strip for pane series, the tooltip card, reference lines, legend (lines added by `derive` are switches that show or hide them), heading that follows the scrub, keyboard scrub and a live region. States: loading (shimmer), empty (one sentence), error. |
| `chart-marks.tsx` | The open map of marks (`registerChartMark`, `chartMark`, `chartMarks`): line, area (stacked when several series), sparkline, bar (grouped), stacked-bar, donut (ring with centre reading and legend with shares), heatmap (calendar of days or a matrix). Over-budget parts of a line or area turn the alert tone. Also pie, radial, radar, treemap, ranked-bar, composed (each series draws as its own `draw`), candlestick, histogram, step-line and step-area. Each mark declares `needs` (named roles, bins, categories); marks only draw, an unknown mark draws as area. |
| `chart-geometry.ts` | Pure geometry: nice ticks, linear scales, monotone cubic paths (Fritsch-Carlson), gap-aware runs, stacking, bar paths with a rounded data end, donut arcs with gaps, heat thresholds and steps, slot centres and nearest slot. Also the open map of curves (`registerChartCurve`, `chartCurve`, `chartCurves`: monotone, linear, step and so on), polar points, polygon paths, squarified treemap tiles and arc paths. |
| `chart-from-records.ts` | `chartFromRecords` (records + placement -> ChartData, continuous time buckets, top groups with the rest folded into Other, reference lines read from the answer), `chartOfPoints`, and the open maps of formulas (including `first`), time buckets, value readers and derivations (`registerChartDerivation`: moving-average, exponential-average, running-total, difference, change-percent, share, rsi, macd). Also reads `placement.series[]` (one measure per role or line) and `placement.bins` (a number cut into ranges). |
| `chart-types.ts` | `ChartData`, `ChartSlot`, `ChartSeries`, `ChartLine`, `ChartLineRow`, `ChartPlacement` (the DATA row), `ChartSeriesRow`, `ChartDerivationRow` (`ChartNeeds` is in `chart-marks.tsx`). |
| `ChartPlacement.tsx` | `ChartPlacement` (a placement drawn, with roll up / roll down by bucket, drill into a slot, Back, and category picks), `ChartPlacements` (a grid of them), `ChartsOver` (charts above a list). |
| `SPECTRUM-UI-LICENSE.md` | The Apache-2.0 notice and full text for the files adapted from Spectrum UI, with the repository, commit and the Trillion files changed. |
| `offer-chart-view.tsx` | Registers the Chart view every list offers; its drawing (`list-chart.tsx`) is fetched the first time a list is drawn as a chart. |
| `chart-choice.ts` | `keepChartChoicesIn({ use, write })`, `useChartChoice(key)`, `keepChartChoice(key, value)`: where a list's own chart choice is kept. The page that has a records store hands it in once (`src/workspace/offer-chart.ts`); with none handed in the choice is kept nowhere, so the chart reaches no workspace store and a public share bundles none. |
| `list-chart.tsx` | The Chart view itself: the person picks mark, the number each role needs (candlesticks) or the number cut into ranges (histogram), formula, split, Line (how it bends), Look and Add a line right on the chart, kept as their record `workspace-preference:chart-view:<list>`. |

## Key Types / Functions

| Type / Function | Signature / Shape | Role |
|-----------------|-------------------|------|
| `Chart` | `({ data, mark?, label, height?, state?, empty?, error?, title?, value?, detail?, follow?, onSlot?, controls?, bare?, className? })` | Draws any ChartData with any registered mark. |
| `ChartData` | `{ slots: ChartSlot[]; series: ChartSeries[]; lines?: ChartLine[]; value_kind?; bucket? }` | What a chart shows. |
| `ChartPlacement` (type) | `{ id, title?, mark, records_path?, where?, reading?, group?, formula?, headline_path?, over?: { field, bucket?, buckets?, since_path?, through_path? }, limit?, lines?: ChartLineRow[], value_kind?, partial_last?, wide?, empty? }` | A chart as DATA. `since_path` and `through_path` bound records and slots to an inclusive answer-defined period, including quiet days; `headline_path` reads an authoritative total and says what plotted bars sum to when they differ. |
| `ChartSeries` (new fields) | `draw?: string` (the mark this series draws as inside `composed`), `role?: string` (which named number it is, for marks that need roles), `dashed?` | A series can choose how it is drawn and what it means. |
| `ChartPlacement` (new fields) | `series?: { reading, role?, formula?, label?, draw?, tone?, dashed? }[]` (one measure each), `bins?: { count?, width? }` (a number cut into ranges), `derive?: { kind, of?, window?, label?, draw?, dashed? }[]` (lines made from a series), `curve?: string`, `fill?: string` | Everything the new marks read; `fill` is written to `data-fill` on the chart root and the look sheet draws it. |
| `ChartNeeds` | `{ roles?: { id, label, formula? }[]; bins?: boolean; categories?: boolean }` | What a mark asks of a placement; the Chart view builds its choices from it. |
| `registerChartDerivation` | `(id, { label({window, unit}), unit?, replaces?, derive(values, { window, all }) })` | Adds a line made from a series. A different `unit` (change-percent, share, rsi) replaces the numbers instead. Unknown ids are skipped. |
| `registerChartCurve` | `(id, (points) => path)` | Adds a way for a line or area to bend; unknown ids use monotone. |
| `slotRows` | `(data, roles, rolePlayers, index) => rows` | The tooltip rows for one slot, pure so it can be tested. |
| `ChartSeries` (stock-chart fields) | `pane?: string`, `derived?: boolean` | `pane` names the strip: none or `main` is the plot, any other name lays the series in a low strip of its own (about 22% of the plot height, one strip for each name, stacked under the plot, sharing the x axis and the crosshair) under the plot on a scale of its own (volume under a price), out of the shared scale, the headline and the derivations; a mark also names pane roles (`pane: ['volume']` on `candlestick` and `composed`), so a series with `role: 'volume'` needs no flag. `derived` marks a line added by `derive`; the legend offers it as a switch. |
| `ChartPlacement` (stock-chart fields) | `ranges?: { id, label, since?: { days?, weeks?, months?, years? } }[]`, `series[].pane?`, `range?: string`, `ranges[].days?`, `ranges[].since: 'year-start'` | `ranges` is DATA for a segmented choice (1W, 1M, 3M, 1Y, All) that narrows the time axis; each `since` counts back from the latest record and the one without a `since` is everything. The choice is kept like the bucket. | `range` is the chosen id, written to the row by `onPlacementChange`; `days` is a plain number of days back; `since: 'year-start'` starts on 1 January of the latest record's year (YTD). All counting is from the latest record, never from today.
| `rangeStart` | `(ranges, chosenId, latest) => number \| null` | The moment a chosen range starts; null for no choice, no `since` or nothing dated. |
| `PaneBars` | `({ name?, series, xs, slot, top, bottom, hover, tone })` | The low strip: each pane series as short bars from zero to its own largest, toned `rise` or `fall` by `tone(index)`, which a mark takes from the candle of the same slot (roles `--chart-tone-rise` and `--chart-tone-fall`). | `name` is the pane (`data-pane`); all series of one pane share one scale.
| `slotRows` (panes) | `(data, roles, rolePlayers, index, panes?) => rows` | Pane series list after the others in an ordinary tooltip, since their size would otherwise put them first. |
| `paneOf` | `(series, paneRoles?) => string \| undefined` | The pane a series draws in: its `pane` name, else the role when the mark lists it in `pane`, else undefined (the plot). Chart.tsx groups strips by it. |
| `DEFAULT_RANGES` | `ChartRange[]` | 1M 3M 6M YTD 1Y All; list-chart gives them to a placement over time that names none. |
| `ChartPlacement` (range change) | `range_change?: boolean`, `ranges[].show_change?: boolean` | Each range choice carries its change under the label: first to last finite value of the first series inside that range, as a signed percent (`+22.6%`), toned `rise` or `fall` by role (`--chart-tone-rise`, `--chart-tone-fall`). `range_change` turns it on for every choice, `show_change` for one; `show_change: false` opts one out. Needs two or more ranges. Idea from TradingView and Compound Planning. |
| `seriesChange` | `(data: ChartData) => number \| null` | Percent change from the first to the last finite value of the first series; null for fewer than two values or a first of zero. Measured against the size of the first, so a rise stays a rise below zero. |
| `changeWords` | `(percent) => { text, tone? } \| null` | The change as words: one decimal, ASCII sign (`+3.2%`, `-1.4%`, `0.0%`); `tone` is `rise` or `fall`, left out when flat; null for null or non-finite. |
| `rangeChanges` | `(input: ChartInput) => Record<string, ReturnType<typeof changeWords>>` | One `changeWords` per range that asks for it, each worked out by building the chart for that range alone (no derivations, no baseline). |
| `ChartPlacement` (baseline) | `baseline?: number \| 'first'` | A value a line or area is measured against; `'first'` is the first value drawn in the shown range. Drawn as a quiet dashed `line.chart-baseline`; stroke and fill wear `--chart-tone-rise` over it and `--chart-tone-fall` under it, through two gradients across the plot split at the baseline's y (roles only, no colour in the mark); the fill fades toward the baseline. The y scale fits the values and the baseline instead of starting at zero. Stacked series and marks that do not declare `baseline` ignore it. Idea from Compound Planning and Origin. |
| `ChartData.baseline`, `ChartMark.baseline` | `baseline?: number`, `baseline?: boolean` | The worked-out baseline, and the flag a mark sets to take one (`line`, `area`, `step-line`, `step-area`). `CartesianContext.baselineY` is its y, null when there is none. |
| `SegmentedControl` item `note` | `{ id, label, note?, noteTone? }` | Shared part: a second, smaller line under a choice (`data-segmented-note`, tone in `data-note-tone`); the track grows to two lines (`data-noted`) and the choice's accessible name reads "label, note". The part holds no colour; the look decides. |
| `ChartPlacement` (`onPlacementChange`) | `(placement) => void` | ChartPlacement hands the whole placement back with the chosen `range`; list-chart writes it like any other choice (saved view settings or the person's own record). |
| `ChartMark` (stock fields) | `zero?: boolean \| ((data) => boolean)`, `headline?: string` | `zero` as a function decides the y floor from the data (`composed` starts at zero unless it holds candles); `headline` is the role whose value is the slot's total (`close`). |
| `ChartLineRow` | `{ value? \| from + value_path + label_path + bucket_path + where, label?, tone? }` | A budget/target line, fixed or one per row of the answer, shown only in its bucket. |
| `startingPlacement` | `(fields: FieldDescriptor[], label) => ChartPlacement` | The chart a list starts with from its own fields (dates over time, money summed, first grouping split); used by the list Chart view and a placed chart naming none. |
| `ChartKept` | `{ bucket?, range?, drills? }` | What a placed chart keeps about itself (the bucket, the range it shows, the slots it drilled into); `ChartPlacement` takes `kept` and `onKeep`. |
| `chartFromRecords` | `({ placement, records, answer?, readField?, groupLabel?, bucket?, range?, since?, until? }) => ChartData` | Placement to data. `range` is the id of one of the placement's `ranges`. |
| `chartOfPoints` | `(points, { label, value_kind?, tone? }) => ChartData` | A short line under a number. |
| `registerChartMark / registerChartFormula / registerChartBucket / registerChartValueReader` | `(id, entry) => void` | Add a member to an open set everywhere at once. |
| `ChartMark.legend` | `{ id, label }[]` | The named numbers whose readings make the one quiet line over the plot (`O 182.1  H 184.0  L 181.2  C 183.5  +0.8%`); left out, the roles the mark `needs`. Roles it lays in a pane are left out. Any mark that declares roles gets the line; nothing checks a mark's name. |
| `slotLegend` | `(data, roles, players, headline, index, read) => { readings, lines, tone, change } \| null` | The legend for one slot, pure: each role's reading, the current value of every derived line (coloured by the series colour it is drawn with), the rise or fall tone and the change from the slot before. `Chart` passes the hovered slot, or the latest when nothing is hovered; drawn as `p.chart-readings` above the plot. |
| `ChartPlacement` (price axis) | `order?: string`, `mid?: number \| 'between'`, `mid_path?: string[]` | `order` is a key of the registered orders (`total`, `number`, `number-descending`, `name`); a number order gives every slot its position `ChartSlot.at`, so a chart spaces slots by price, not evenly. `mid` is a number or `'between'` (halfway between the best bid and the best ask); `mid_path` reads it from the answer. Worked out into `ChartData.mid`. |
| `registerChartOrder` / `chartOrders` | `(id, { compare }) => void` / `() => string[]` | Another slot order is one registered entry. |
| `ChartSeriesRow` (sides) | `where?: { path, one_of }`, `curve?: string`, `bar?: string` | `where` keeps only the records at one side (bids and asks out of one list of levels); a slot where none pass holds nothing (null), never zero, so each side is its own run. `curve` bends one series differently from the chart (`step-before` for bids, `step` for asks). `bar` (ranked-bar) names the id or role of the series whose values set this row's bar length. |
| `ChartDerivationRow` (cumulative) | `id?`, `from?: 'end'`, `instead?: boolean` | `from: 'end'` adds up from the last slot back (a bid total grows outward from the mid price); `instead` draws the result in place of the series it is made from, keeping its id, role, tone and mark; `id` names the line so a ranked-bar `bar` can use it as a length. |
| `valueCentres` | `(ats, left, right, mid?, gap?) => { centres, slot, midX }` | Pure geometry: x for slots placed by a number, proportional, with `gap` pixels opened at `mid`. `Chart` uses it when every slot has `at`, and draws `line.chart-mid` at `midX`. |
| `distanceFromMid` | `(place, mid) => number \| null` | How far a place is from the mid, as a percent of it (negative below). The tooltip writes it as "From mid" under the price and the amount so far. |
| ranked-bar `data-behind` | `ol.chart-ranked[data-behind="true"]` | When any series names a `bar`, each row's fill sits behind it (right-aligned, an 18% tint of its series tone, all series on one scale); the length-source series is not drawn as a column and its value is written beside the amount. Without a `bar`, the bar follows its own values as before. |
| `Formula.additive` / `formulaAdditive` | `additive?: boolean` / `(id?: string) => boolean` | A formula says whether its slot values add up across slots. `sum` and `count` do (the default); `average`, `most`, `least`, `first` and `latest` read a level and set `additive: false`. `chartFormulas()` lists it too. A registered formula declares itself, nothing checks a name. |
| `headlineNumber` | `(data, { mark, formula?, series? }) => number \| undefined` | The big number over a placed chart, from data: the mark's `headline` role (the close for candles), else the last role it needs that is not in a pane, gives that series' latest reading, never a sum. Otherwise the plotted series (lines from `derive` and pane series left out) are added together when every formula the placement reads with is additive, and the latest slot's value is used when any is a level. |
| `ChartMark.headline` (candlestick) | `headline: 'close'` | The candlestick entry names `close` as its headline role, so the headline of an OHLC chart is the latest close. |
| `legendSeries` | `(series, mark) => { series, index }[]` | The series the legend offers as swatches. A series playing a role the mark consumes (its `needs.roles`, `legend` or `pane` ids: open, high, low, close, volume) is left out, since the mark draws it; derived lines (such as "7 day average") and series with no role stay. `index` is the series' place in the chart so its colour is unchanged. |
| `labelStride` | `(widths: number[], slot: number) => number` | Thins band and category axis labels: the smallest k such that every shown pair k slots apart clears each other, using each label's estimated width (longest unbreakable word, 6.2 px per character) plus an 8 px gap against the slot width. 1 (show all) when labels fit. Histogram ranges and category names use it, every k-th label is drawn. |

## Usage

```tsx
<ChartPlacement
  placement={{ id: 'cost-by-day', title: 'Cost per day', mark: 'stacked-bar', records_path: ['days'], reading: 'dollars',
    group: 'group', over: { field: 'day', bucket: 'day', buckets: ['day', 'week', 'month'] }, value_kind: 'money', partial_last: true,
    lines: [{ from: ['budgets'], value_path: ['most_dollars'], label_path: ['label'], bucket_path: ['period'] }] }}
  records={[]}
  answer={spendAnswer}
/>
```

## Licences and sources

Geometry numbers follow shadcn/ui charts (MIT); anatomy from the owner's saved dashboard screenshots, X saves and Arc sites, Mobbin (Copilot Money budgets, Framer usage limit line), 21st.dev Balance Chart (keyboard scrub) and Spectrum UI (Apache-2.0, hatched partial bars; no code copied for those). The monotone curve is written from Fritsch & Carlson (1980). Categorical palette and status tones: the dataviz reference palette, validated light and dark.

Spectrum UI charts: the pie, radial, radar, treemap, ranked-bar, composed, candlestick, histogram, step-line and step-area marks, the derivations, the curves and the picker choices are adapted from Spectrum UI (https://github.com/arihantcodes/spectrum-ui, Apache-2.0, commit acdc998c). Each adapted file carries an "Adapted from Spectrum UI" line naming the source file and what changed; the notice and licence text are in `SPECTRUM-UI-LICENSE.md`.

Stock-chart interactions (ideas only, never colours or fonts) come from the owner's saved references: a crosshair on every cartesian mark (a thin vertical guide, a horizontal guide at the hovered value and a value tag on the axis edge, styled with quiet roles in chart.css), a volume strip under candles, a range choice and switches for added lines. See `<scratch>/2026-10-07/spectrum-charts/engine-done.md` for which reference each came from.

Edge labels: a band or category x label whose centred box (estimated with LABEL_CHAR_WIDTH) would cross the chart's left or right edge is anchored to start, or end, at that edge so it is never cut off.

Axis labels that sit at uneven places (a price axis, categories on a line) are thinned by `labelsClear` (Chart.tsx): walking from the left, a label is kept only when the box where it is really drawn (centred, or held to start at the first point and end at the last) starts LABEL_GAP after the last kept box. Time axes keep their even spacing and named bands keep `labelStride`.

Tones: `toneColor(tone, last)` in chart-marks.tsx is the one place a tone becomes a colour role: the look's own `--chart-tone-<tone>`, else the tone it stands in for (rise reads as good, fall as critical, the `TONE_STANDS_IN` data), else `last`. A series that says `tone: 'rise'` (the bids of a book) therefore draws green even when the look sets no rise tone.

Colours on a public share page: chart.css reads `--color-foreground`, `--color-muted-foreground`, `--color-card` and `--color-border`; the share page's `.page-view` host maps them onto the page's own roles (`--page-ink`, `--page-soft`, `--page-card`, `--page-line`) so a dark look draws white chart ink. The calendar heat map sizes its cells from the card width (12 to 36px), the treemap writes a two-line label and leaves tiny tiles unlabelled, and the readings line wraps on a phone.
