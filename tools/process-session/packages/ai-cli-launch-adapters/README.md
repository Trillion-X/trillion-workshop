# ai-cli-launch-adapters

Owner of the `prop:cli_registry:*` schema: the DATA that describes every runnable AI pipe (CLI process, local daemon, cloud HTTP) and the canonical resolution/derivation seams over it.

## Ownership

This package owns the single composite `cli-registry` projection. It folds the
AI CLI registry namespace and the terminal package's `terminal_launch` extension
at the stable `cli-registry` address. Startup packages provide composition only;
they do not define this projection.

## The `ai-model-invocation-option` record

One per (cli x declared model), at `package::ai-cli-launch-adapters::model-invocation-option::<cli>::<model>`: `{kind, id, model, agent_ref, label, description?, provider_label, transport, transport_priority, capabilities, descriptor_ref?, is_default, status}`. Any surface's by-kind option fold (`options_address` / config `options.kind`) lists the full runnable catalog from these; selecting one yields both routing hints (`model` + `agent_ref`) for a producer dispatch.

## The `ai-provider-option` record

One per distinct `provider_ref` this package writes into its model descriptors, at `package::ai-cli-launch-adapters::provider-option::<provider>`: `{kind, provider_id, name, vendor}`. `provider_id` equals the descriptor's `provider_ref` byte for byte (with the `ai_provider:` prefix), because consumers such as `agents-hub` resolve it by equality with no normalisation. The fact lives here and not in a configuration surface because this package authors the identifier; retiring any surface can no longer orphan it. Seven rows today: anthropic, google, openai, ollama, zai, alibaba-cloud, moonshot-ai. `ai_provider:local-owner` appears only as a `serving_provider_ref` and has no row.

## Dependencies

**Depends on:** its own cli-registry facts; `ai-model-descriptor` published-records read generically by kind, which this package also publishes for its own catalog — DATA seam, no import.
**Depended on by:** every caller that runs a prompt against the selected provider (via `action:resolve-chat-launch` Envelope dispatch — e.g. content-production, chat's producer path) and every surface folding `ai-model-invocation-option` options. No package imports this package's modules except its own scripts.

## Invariants

- Pure resolution/derivation — never executes a CLI, never touches network/log.
- Zero hardcoded provider/CLI/model/flag names in code (regression-tested); every name lives in registry DATA rows.
- Automatic routing policy seeds live at `current-item/attribute_fact`; connection and discovery outcomes live at `current-item/published-record`. The producer reads both projections. A provider fact on only a property-specific fold-input path is not routing truth yet and must not be called connected.
- Catalog lifecycle: tombstone (`status:"retired"`), never null-retraction (a null payload poisons boot hydration).
- Deterministic derivation: same rows in, byte-same records out (engine same-content dedup makes refresh idempotent).
