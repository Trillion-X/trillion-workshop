# Media Composition Read Data

Projection and layout helpers for Media Composition package data.

## Files

| File | Purpose |
| --- | --- |
| `read-media-workspace.ts` | Converts owner-fed media evidence rows into sources, lanes, panels, selections, edit decisions, and markers for the UI. |
| `compose-timeline.ts` | The PURE fold: `composeTimeline(view)` folds the ordered `view.editDecisions` (`FOLD_ACTIONS` keyed by `decision.action`: split / trim / move / delete / set-transform / add-source / ...) into a MaterializedComposition. `set-transform` merges an `extractTransform(params)` bag onto a clip's `ClipTransform`. A NEW per-clip DATA field = add a camelCase field to `ClipTransform` + parse it in `extractTransform`; `set-transform` merges it and `materialize-edl.ts`'s generic `clipRow` pass-through emits it on the EDL for free (e.g. `effects` / `lookStack` -> `segment.effects` / `segment.look_stack`, the effect-registry per-clip effect stack). Any editor/agent authors edit-decisions written via the `action:write-media-composition-record` workflow action; never hand-roll clip math. |
| `materialize-edl.ts` | SSOT translation MaterializedComposition -> contract::edl for `action:video-compose`; source resolution injected; per-clip property grammar passes through verbatim (the generic `clipRow` pass-through lands EVERY `ClipTransform` field on the EDL as `camelToSnake(key)` except UI-only/irregular keys, so new DATA fields need zero edits here); unresolved sources reported, never dropped. Tested in `__tests__/materialize-edl.test.mjs` (5 tests: determinism/SSOT, ordering+passthrough, unresolved reporting, exclusions, encode DATA). |
| `adjustment-layers.mjs` | Shared validation plus browser-preview and FFmpeg filter compilation for timed adjustment layers. Optional exposure, temperature, and hue controls stay neutral on older rows; values are bounded before filter construction. |
| `layers-to-edit.mjs` | The one translation of sound and picture layers into edit fields, shared by the editor's Layers panel and the `tool:mix-sound-layers` / `tool:layer-pictures-over-video` Workshop tools: `layersToEdit({ sounds, pictures, loudness }, { frameWidth, edl })` -> `audio_graph.narration` (fades, `duck`), `image_overlays` / `video_overlays` (centre at `x`,`y`, width `size`, `layer_order` back to front), `master_loudnorm`; `layerProblems` (every reason in plain words), `soundFromMusicBed` (an older single music bed as a sound layer), `layerSourcesAreFiles(edl)` (every laid-over source is a file identity; `/work/api/media/edit` and `/render` refuse others). Tested in `test/layer-over-video.test.mjs`. |
| `reframe-camera.json` | DATA: how the reframe camera moves (`do-work/auto-reframe.mjs` planCamera): `steady_seconds` (running median span), `hold_zone` (share of the crop window the subject may move in before the camera moves), `max_speed` (crop-window widths per second), `ease_seconds` (how gently pans start and stop), `keep_within` (how far the simplified path may leave the planned one), `cut_beyond` (crop-window widths the subject may get ahead before the camera cuts), and the motion blur on each move (`planMotionBlur`): `shutter_seconds` (how long a frame is exposed), `least_streak` (the smallest smear drawn), `streak_step` (how smears are rounded so neighbouring moves share one blur). |
| `looks.json` | DATA: the looks a clip can wear (`looks[]`: id, label, group, the render fields it sets), their `groups` (a group marked `one_at_a_time` keeps one pick), per-clip `adjustments` (id, label, bounds, neutral value, the render field its number goes to, optional live-preview CSS), `timed_adjustments` and the frame `fits`. Ported from the Mac editor's colour presets: the camera log conversion, seven colour grade steps and their two stacks, widescreen bars, dark corners, colour fringe, film grain, glow, plus the renderer's effect styles. Adding a look is a row. |
| `looks.mjs` | The one mapping from colour choices to render fields: `clipColourFields({ looks, adjust, framing, match }, [w, h])`, `chooseLooks`, `adjustmentFields`, `adjustmentPreviewFilter`, `framingFields`, `colourMatchFields`, `lookCanBeTimed`, `timedLayers({ adjustments, looks }, duration)`, `mergeFields`. Pure; used by the editor's Colour panel, `do-work/grade-a-video.mjs` and tests (`test/media-look-panel.test.mjs`). |
| `preview-grade.mjs` | The fast preview of a video's colour choices: `frameGrader(adjust)` answers a function that changes RGBA frame bytes in place the way the render will (a twin of each ffmpeg filter keyed by its render field: eq, colortemperature, vibrance, exposure, in `looks.json` `preview_chain` order), or null when nothing would change; `unpreviewed(adjust)` names render fields with no twin; `previewedAdjustments()`; `kelvinToRgb`. Pure; used by the Controls screen (`src/workspace/controls-previews.tsx`) and `test/made-controls.test.mjs`. |
| `stored-bytes.json` | The files the renderer reads by address (`package::media-composition::stored-bytes::<name>` -> `read-data/luts/<file>`), read by `do-work/video-compose.mjs` beside the part's own declarations. |
| `luts/` | The colour grade files (`.cube`) the looks name; they sit in read-data so every container tool that carries read-data has them. See `luts/README.md`. |
| `caption-styles.json` | DATA: every caption style a video can be captioned in (`styles[]`: id, name, font, size, bold, italic, outline, `shadow` {x, y, blur, spread, colour, opacity} (an offset alone is a drop shadow, blur or spread a soft halo under the words; null is none), `colours` {spoken, upcoming, outline}, `position` {x, y} of a caption's bottom-centre, `reveal` line or karaoke, `grouping` of words into lines, `preview` {fonts, background}); sizes are pixels on a frame whose shorter side is `measured_at_short_side`; `default` is the style used when none is chosen. Holds every style the Mac editor offered, plus `white-words-light-up` (the owner's reels: SF Pro Text, white words over grey ones, a soft halo at no offset; `said_by` records where it came from). Adding a style is one row. `settings` are the inspector rows (parts/ui TuningPanel sections, each row's `path` the field it changes); adding a detail to tweak is one settings row. |
| `caption-styles.mjs` | The one caption style builder (pure): `CAPTION_STYLES`, `DEFAULT_CAPTION_STYLE`, `CAPTION_STYLE_SETTINGS` (the inspector rows a style is tweaked with, from the catalog's `settings`), `CAPTION_MEASURED_AT`, `resolveCaptionStyle(id \| own row starting from an id)`, `timedWords(line)` (a line's own word times while they still spell it, else its text spread over its time), `scaledShadow(shadow, scale)` (a shadow row's pixels on the real frame), `captionAss(lines, style, { width, height })` the burned-in subtitle through `../do-work/author-karaoke-captions.mjs`. Used by the editor's Captions panel (`src/workspace/media-edit/captions-panel.tsx`) and `../do-work/cut-and-caption.mjs` (tool:add-captions, tool:cut-and-caption). |
| `caption-lines.ts` | Pure grouping of spoken words into timed caption lines: `groupWordsIntoCaptionLines(words, { maxWords, maxChars, maxGap, maxSeconds, breakAfterSentence, casing })` (casing writes a capital at each sentence start and on the style's always-capital words, `casedWords`), `wordsOf(transcript)` (any kept transcript shape, read by shape), `captionLinesForCut(words, from, to, grouping, transcriptFrom, at)` and `captionLinesForEdit(stretches, grouping)` (lines for a whole edit of stretches, on the edit's own time). |
| `read-media-editor-layout-state.ts` | Defines the package-owned five-pane editor layout and the compatibility predicate used before persisted screen-arrangement state can replace it. |

## Rules

- Media Composition owns the required editor panes and media surface inputs.
- Screen Arrangement owns layout mechanics, but it does not know which media panes are required.
- Saved layout state is accepted only when it still contains the package-owned editor workspace shape.
