# Media Composition Do Work

The video.compose EDL compositor (the package's ONE render authority, run by `action:video-compose` through compute.process) plus edit-decision/record writers.

The source CLI also accepts a numbered image pattern as a clip's `source`, with explicit positive `source_frame_rate` and `in`/`out`. This permits raw frames from the existing record-a-web-page owner to enter the same compositor without a second encoder. Stage reuse uses the shared BLAKE3 identity owner and binds the bytes of every regular input or numbered frame, so changed frames invalidate a prior output even when their size and mtime match. This is local source behavior; hosted registration and deployment remain separate states.

The identity owner is the pure `parts/content-identity` part; the existing workspace import path re-exports it. File inputs and final movies are read in bounded chunks. Existing compositor container bundle declarations carry this owner and `@noble/hashes`, including its license, so source adoption does not leave a new unresolved root-relative import. Output `video_multihash` now uses the same `1f:` BLAKE3 identity. The byte and streaming forms are checked for equivalence; old source receipts are retained as their original epochs.

## Rules

### Local source composition and native voice

`author-voice-script.mjs` is a local source-root adapter for the installed Showtime
`voice script` producer. It translates checked, ordered narration DATA and explicit
speaker profiles into that producer's existing JSON contract. It uses the shared
heavy-work admission owner and checks source and derived bytes again at the
admitted start. It preserves separate source epochs and reads back the actual
timeline words, speaker profiles, WAV header and native readback.

This caller is not a registered or deployed container tool. It does not add a
speech engine, concatenate audio itself, publish content or qualify source meaning,
listening or author acceptance. The focused producer tests cover copy refusal,
exact output binding, recoverable epochs and mutations during queueing, on synthetic
fixtures in a temporary folder.

Run from the Workshop with `node tools/media-composition/do-work/author-voice-script.mjs
--input <copy.json> --outdir <new-voice-directory> --rules <rules.json>`. The input may be
any path; the person's copy rules (a list, or `{ "rules": [...] }`) come from the caller.
The spoken narration words go through `tool:check-copy` (`checkCopy`); a refusal, failing
or held verdict stops before anything is synthesized. The caller executes the adopted
`narration/produce.py` through an installed dependency runtime that `program-here.mjs`
finds in the folders `narration/runtime.json` names. An installed Showtime launcher argument is refused. `narration/LICENSE` and
`source-adoption.json` preserve the licensed origin; no old renderer, launcher,
installer or MCP service is adopted. Native synthesis uses the existing source
speaker with exact-voice failure rather than substituting another voice.


- This folder owns media-composition export request structure and ffmpeg command assembly.
- compute.process inline input encoding comes from `@bitfield/runtime-kit/protocol`; this folder must not import caption-renderer source or copy base64 encoders.
- Export sources are passed as generic process inputs and addressed output chunks, not package-local generated files.
