# What the cost runs establish

The historical `s2h-exact-order-search-segments-daily` candidate executes real
SQLite work in a separate research implementation. It is not the production
S2h implementation. A source fingerprint changing does not make that candidate
measure newly added account, routing, command, or Namespace code.

`product-s2h-current` calls the production S2h and observed SQLite supply with
shipped settings. Its contract tests cover values, lists, search, history,
receipts, deletion and reopen. It measures the **storage slice**. It does not
claim a complete native request, account admission, affinity selection, tool
execution or physical owner-wide erasure. Secondary-index invoice units and
mid-statement interruption are explicitly unmeasured.

The generic engine processes events serially. A burst of 100 actors is a
cost/arrival experiment, not 100 real threads or a hosted capacity benchmark.
The remote supply probe in `src/storage/supplies/tests/roundtrips.rs` separately
calls the actual production storage APIs on isolated local protocol servers.
Its network rounds are not provider billing units.

## Editable scenarios

- `usage/architecture-profiles-2026-10-31.json`: five isolated marginal cases,
  not complete personas. Library first page/fetch-all and shared/separate
  resource controls must not be added together.
- `usage/product-architecture-table-2026-10-31.json` and the matching
  `surrogate-architecture-table-2026-10-31.json`: same workloads, two seeds,
  three fault profiles, full 30-day horizons. Retention and fixed restart days
  cannot be inferred by scaling two days to a month.
- `usage/object-traffic.json`: independent byte/request/backup sensitivities.
  `architect/crates/workload-simulation/examples/object_traffic.rs` consumes
  these through the shared `cost::invoice::Schedule` arithmetic owner.
  Provider included quantities are pooled over a whole billing scope;
  storage-linked egress, decimal/binary GB, rounded billing blocks and tiers
  are explicit. These are hypothetical traffic patterns, not measured
  customer traffic or proof of machine capacity.

## Read the output before comparing totals

Cells carry attempted, acknowledged, failed, skipped, unsupported and missing
coverage counts. Failed or missing useful work cannot establish a cheap,
complete result. All model-wide unpriced components enter the cell unknowns.
A lower-bound subtotal is not a complete invoice. Seed/fault min/max is not a
confidence interval for uncertain customer behavior or supplier capacity.

The generic `List` intent keeps its newest-changed semantics: the product
adapter reads the production changes feed and filters/sorts the result, so its
first-50 reply still pays for that scan. Historical runs using that intent
remain valid for the old adapter behavior and are preserved as baselines. The
bounded Library workload now uses a separate `ListPage` operation mapped to
the product `Records::list_page` cursor API. Do not interpret the old `List`
rows as the native Library screen's bounded page cost. The direct
`actual_product_bounded_page_and_fetch_all_work` probe uses the real API on
12,180 synthetic rows and checks identical prefix values. Its October 31 run
measured first-50 at 1 statement/51 visits versus fetch-all at 244
statements/12,666 visits, with no writes on either side. These are storage API
work counts, not a complete UI request or invoice.

Run reports declare each engine and candidate meter's unit and aggregation.
Unrecognized, unreported, or configured-but-unpriced counters stay explicitly
unknown. Reports from the usage-table runner also separate physical start/end
timestamps from the simulated day window and include BLAKE3 identities for the
run's meter-producing source and run inputs. They do not imply that the
simulation's source revision is the installed product revision.

Freeze source before building, run the exact artifact against the snapshot,
and retain source/binary identities. Never mutate a snapshot while it runs.
Use the declared contained Cargo owner; the package's `.cargo` settings enable
SQLite statement scan status, which the observer requires. An unsupported
observer or refused operation must fail or stay unknown, never become zero.

Reports and dated official-price evidence for the October 31 audit live in
ai-command-center `notes/projects/usage-cost-tables-2026-10-31/`.
No deployment, paid traffic or live-account mutation is required by these runs.
