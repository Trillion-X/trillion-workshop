# Visual Database Browser Surface

This folder contains the React surface for `visual-database`.

The surface renders descriptor-driven views over generic addressed records. Lane names, view kinds, value domains, and actions come from package data, not hardcoded task or idea states. Every visible field is editable in place: editors dispatch by VALUE SHAPE through an open registry, never by field name.

`mount-visual-database.tsx` is the browser package entry. It reads through the
generated package-scoped Runtime Kit hook and keeps those reads inside the
material `ErrorBoundary`, so a package input/runtime failure cannot collapse the
mounted root into a blank screen.

## Files

| File | Purpose |
|------|---------|
| `VisualDatabaseSurface.tsx` | The arrangement surface: views (list/board/timeline/swimlane/table/graph), rows/cards, composer, new-list form, labeled complete `Fields` schema editor, choice settings, drag re-order (fractional keys + migrate-by-touch), tree-projected subtodo rendering, view tab bar and layout switcher (derived from the renderer registry). The schema editor lists declared and detected fields, uses descriptor-array order as the SSOT, edits labels/types, safely removes unreferenced descriptors, requires explicit `Add to fields` promotion for detected keys, and composes the existing nested choice editor. The `table` view is a real descriptor-driven `<Table>`: headers from display-field labels, `FieldControl` per cell, columns = the descriptor set. The list view windows its bucket-header/record stream through the shared ui `VirtualList` above 150 items (O(visible) DOM at any record count) and resolves child lookups through the memoized `treeProjectionForRecords` `nodeByKey` index instead of rebuilding the tree per row |
| `field-editors.tsx` | Shape-keyed editor registry (`fieldEditorRegistry`, exported for composition-level extension) + the descriptor-driven write path (`writeField`, `buildRecordWrite`, `applyFieldWrites`) + generic field controls (`FieldControl`, `FieldPills`, `ZoneEditor`, `CompleteControl`, `OverflowMenu`) + tone mappers (`toneVariant`, `toneToStatusDot`). The heavy attachment file editor (`FileEditor`, CodeMirror) is lazy-loaded (`React.lazy` + `Suspense`) so the module — and every consumer — stays free of the code-editor graph |
| `field-editor-kit.ts` | Pure, dependency-light leaf shared by every field editor: the editor CONTRACT (`FieldEditorProps`, `FieldEditorComponent`) + the value-free helpers (`humanize`, `stop`, `toneColor`, `domainValueColor`). Imports read-data types only — no show-layer component, no I/O. Lets editors be authored + unit-tested without dragging the attachment/CodeMirror graph |
| `grid-interaction.ts` | Pure grid physics (W7): keyboard traversal, view column state, ranges, addressed-expression fill (`buildFillDownExpressionWrites`) with declared relative-ref transforms, and TSV projection |
| `grid-interaction.test.ts` | Traversal clamps/wrapping, column-state round-trip + resurrect-safety, fill-down batching + read-only/derived skip, TSV normalization |
| `add-field.tsx` | Runtime "+ Field" (W7): builds ONE descriptor row (shape list enumerated FROM the editor-kit registry — no literal array) with optional `derive` by address (Formula/Ask AI/Linked records); commits via the owner's fields-record writer seam |
| `cell-expression-editor.tsx` | Accessible per-cell literal/derive editor. Source choices are live evaluator descriptors; every addressed dependency has editable record/field controls |
| `add-field.test.tsx` | Descriptor assembly per source + registry-provenance grep test |
| `rating-editors.tsx` | The `scale` + `grid` generic shape editors (registered into `fieldEditorRegistry`): `scale` = bounded numeric readout via the ui `Slider` (bounds + anchors are the descriptor's domain values; commits a NUMBER); `grid` = big-tap single-select over the domain (same commit contract as `choice`). ZERO domain vocabulary — the same two editors serve NPS/CSAT/focus/mood/any rating survey. `ui` primitives only |
| `RecordFormSurface.tsx` | The descriptor-driven FORM (the form counterpart of the board surface): a vertical column of `label + shape editor` over a `VisualDatabaseModel`, with a single data-defined submit. Compose (no `record`, synthetic draft → create) or edit (`record` present → write back). Submit prefers a `VisualDatabaseActionDescriptor` via `onInvokeAction`, else a generic `writeRecord` create. `visibleWhen` gates fields. Home for order tickets and new-connection/new-booking/composer forms |
| `RecordMetricRow.tsx` | Projects one record + metric field descriptors → `MetricCell[]` (via `extractFieldValue` + a caller `formatValue`) and renders the shared ui `MetricRow`. The metric strip of any surface; WHICH metrics + their order are DATA |
| `ComposeFieldSet.tsx` | Flat-list compose field-set (capability fields → editors). SUPERSEDED by `RecordFormSurface` (model-native); retained only until the order ticket migrates onto `RecordFormSurface` |
| `mount-visual-database.tsx` | Browser package entry: data inputs → `decodeVisualDatabaseModel` → surface, inside `ErrorBoundary`. A mount may pass a per-surface `surfaceInput` (via `props.surfaceInput`) to render its OWN board DATA — multiple independent boards by data |
| `select-visual-database-input.ts` | `selectVisualDatabaseInput(surfaceInput, key, globalRaw)` — per-surface board-input choice: a key the `surfaceInput` carrier holds is that instance's SSOT; omitted keys (and `null`/`{}`/non-object) fall back to the global read. The multi-board-by-DATA primitive (generalizes analytics' `selectAnalyticsSource` to visual-database's 4 inputs) |

## Key Types / Functions

| Export | Signature / Shape | Role |
|--------|-------------------|------|
| `VisualDatabaseSurface` | `({ model, writeRecord?, onInvokeAction? })` | The surface. With a `RecordWriter` every mutation is live; without one it renders read-only. Record payload writes are staged through the same decoded model so completed/moved/edited records re-bucket immediately and roll back on failure |
| `fieldEditorRegistry` | `Record<string, FieldEditorComponent>` | Shapes → editors: `text`/`longtext`, `number`, `flag`, `choice`, `multi`, `temporal`, `reference`, `attachments`, `scale`, `grid`. Registry-first lookup, text fallback for unknown shapes (degrade, never error). `scale`/`grid` live in the `rating-editors` leaf |
| `FieldEditorProps` | `{ record, descriptor, value, domain, commit, readOnly, fieldActions?, model? }` | The editor contract (defined in `field-editor-kit.ts`, re-exported here); `commit(null)` clears the field |
| `ScaleFieldEditor` / `GridFieldEditor` / `scaleBounds` | rating shape editors (`rating-editors.tsx`) | `scale` = ui `Slider`, DATA bounds/anchors from `domain` (`order` = position, `label` = anchor), commits a NUMBER; `grid` = big-tap cells over `domain`, commits `candidate.id` (or null). `scaleBounds(domain)` derives `{min,max,minLabel,maxLabel,anchors}`, 0–10 default when domain is empty |
| `writeField(write, record, writes)` | one record + N field writes → ONE write entry | Deep-set along each descriptor's write path into a path-copied payload; non-object payloads resolve to read-only no-op |
| `FieldControl` / `FieldPills` / `ZoneEditor` | generic controls | Derive shape → resolve domain → dispatch → commit. The pill row shows ONLY fields carrying a value on THIS record (Amie density rule); the add-field dropdown admits declared fields only, while discovered payload fields stay reachable through `All details`. `ZoneEditor` renders title/body through the seamless ui `InlineEditText` (text IS the input; body is multiline auto-growing) |
| `CompleteControl` / `OverflowMenu` | record affordances | `CompleteControl` renders the ui `CompletionRing` (hover check preview, success fill) and toggles every lane-bound status face between the completion lane and the first non-complete lane, optimistically; `OverflowMenu` completes / copies title/id / deletes through the same addressed record write primitive |
| `displayTitle` / `displaySubtitle` / `shortDate` / `isMachineString` / `toneVariant` | display helpers | Machine identity never renders as a heading; open tone strings map to Badge variants with neutral fallback |
| `toneToStatusDot(tone)` | `(string \| undefined) => StatusDotStatus` | Open tone string → ui `StatusDot` status (`success`/`warning`/`error`/`info`/`accent`/`idle`); unknown/neutral → `idle`. The one home for the tone → status-dot mapping |
| `RecordFormSurface` | `({ model, record?, values?, onChange?, submitAction?, onInvokeAction?, writeRecord?, submitLabel?, onSubmitted? })` | Descriptor-driven form over a `VisualDatabaseModel`. Compose (synthetic draft) or edit; submit via data-defined action or generic `writeRecord`. Fields = model fields minus structural roles; `visibleWhen` gates them |
| `RecordMetricRow` | `({ record, descriptors, formatValue, align? })` | Record + metric descriptors → ui `MetricRow`. `formatValue(value, descriptor) => { value, tone? }` owns all presentation |

## Interaction invariants

- Drag a card between columns: writes the GROUPING descriptor named by the active `view-group` projection rule (kanban-by-anything), composed with a fractional sort key in the SAME payload when dropped between cards.
- Drag a row in list view: one `keyBetween` write; if neighbors hold legacy numeric order values, the whole visible sequence is respread in ONE atomic batch (migrate-by-touch). The affordance only appears under manual sort (not in timeline). A ui `DropIndicator` insertion line shows above the hovered row; board columns highlight via `Card selected` while a record drag is over them.
- Collapsed rows render the date as the LIVE temporal editor (DatePicker popover on the pill), not a static badge; people badges render muted.
- Expanded property strips are controls, not collapse handles: date, status, priority, add-field, and overflow interactions stop row-click bubbling. Chosen field faces use the same compact property-button family (dot/icon + label where relevant); empty field placeholders stay behind the one Add field control. When two temporal descriptors render the same visible date, the pill row shows one face by default and leaves the duplicate descriptor behind Add field for explicit use.
- Attachment/proof fields render through the `attachments` shape editor: file paths, URLs, log-addressed refs, content/CAS refs, and inline preview content stay raw in storage while showing human chips. Clicking a chip opens an inline detail panel; inline content and loaded log records render through `file-content-renderer`, local file refs can preview/reveal/copy, URL refs can open/copy, and no attachment is reduced to a copy-only ref menu.
- Declared fields auto-render when present and are the only fields offered by the primary Add field control. Discovered payload keys are data the board found, not proof of primary UI placement; they stay accessible through the `All details` inspector for the current record instead of becoming selectable product options.
- Completion checkboxes come from the semantic completion lane. View data should provide `tone: "success"`; color-only view data using the shared green success token is decoded to that tone so old user-created lists still get the same Fable/Amie checkbox anatomy.
- Status and priority choice fields use one compact chip face: the color dot carries the state/tone and the shared chip surface keeps property rows visually coherent.
- Field names, types, order, and inline domains are edited through the labeled
  `Fields` toolbar control. Nested choices write their complete field-domain
  values to the caller's fields owner. Custom color creation uses the shared ui
  native color picker that drawing/mark tools use, then stores the human color
  name in Visual Database data. User-facing copy says Fields/Colors/Choices
  instead of descriptor/domain/payload vocabulary.
- Assignee fields render as square `PersonTag` faces, not raw chips. Stored placeholder values such as `unassigned` are treated as empty; clicking an assigned face exposes remove/add/action options without adding a naked plus button beside the face. The suggestions come from the `record-people` field domain (`fromRecords` plus `open`), so current shipped suggestions are AI agent profile records and typed names can still be stored as ordinary assigned values.
- Assignee chips can expose data-declared actions. The current action label is `Ask to work on task`; it requires the plain text prompt before dispatch so an empty instruction cannot create a hidden task.
- Feed-projected record addresses are already-encoded multihash hex — `record-writes` routes them through the runtime's `multihash_hex` mode, never re-hashed. This is why edits stick.
- List, board, nested child rows, child-tree lookup, and ancestry checks use the durable record address as their UI/tree identity when available. The data `id` remains link/search data; the address is the identity that prevents sibling controls from being reused across duplicate/repaired records and keeps a clicked child delete pointed at that child.
- Record payload edits are optimistic at the surface: completion, status moves, dates, assignees, and undo write the addressed payload, stage that payload into the generic model projection, and roll it back only if the write fails. Checking a task therefore moves it into Completed immediately instead of painting only the checkbox, and every descriptor using the lane binding receives the same completion value so a row cannot show a checked box beside a stale "To Do" status face.
- Delete is optimistic at the surface: the menu writes `payload: null` to the addressed record and the surface hides that exact record immediately, restoring it only if the write fails.
- Multi-valued grouping fields: a record appears in the column of each value; a drop replaces the dragged-from value (generic set-move rule).
- Link-role descriptors project list rows through the shared `treeForRecords` primitive into parent/child groups; child rows never render as top-level list siblings. Parent and child expand chevrons use the same small visible button surface and one right-chevron glyph that rotates open with token timing. Every depth gets the same title, body, completion, field-pill, attachment, and action surface instead of a reduced child-only renderer. The sub-task composer is an input-first row with a hover-revealed checkbox affordance and no decorative plus icon. The link field itself is structural and does not render as a property chip; status, priority, date/due, assignee, proof, and attachment controls stay visible instead.
- Composer payloads are assembled from descriptors' write paths — no hardcoded payload keys, no default-lane or default-kind fallbacks (honest absence).
- List view groups top-level records into Amie date buckets relative to today (Earlier/Yesterday/Today/Tomorrow/Later/No date) via `dateBucketOf`; completed top-level records (tone-driven completion lane) always live in a trailing Completed section, collapsed by default. Today and Completed persist at 0-count so structure survives an empty list. Child records never render as list siblings; they are reached through their parent row and counted by the same hierarchy projection.
- List, board, table, graph, and the surface heading all count/render hierarchy roots for top-level task layouts. Raw child records remain in the model for search, child lookup, and editing, but they do not become sibling rows/cards just because a layout changed.
- Hierarchy projection prefers declared `role: "link"` field descriptors and falls back to the generic parent-reference field shape (`parent` / `parent_id`) when a package feed carries parent links but the runtime field list did not expose the role cleanly. The fallback is only a descriptor-selection repair; child rows still come from ordinary record data, not June 22-specific code.
- The composer shows a `Kbd` N hint at rest backed by a REAL window-level N binding (focuses the composer unless an editable element is active); Create replaces the hint once there is content.
- Board columns carry Linear header anatomy (tone badge + count + per-column "+") and a Notion-style `LaneComposer` "+ New" row at the column bottom — an inline borderless input that creates directly into that lane with an order key after the column tail (Esc cancels, blur-on-empty closes). Cards show a `DropIndicator` insertion line while a record drag hovers them.
