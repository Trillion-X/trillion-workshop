# Isolated module surface

`IsolatedModuleSurface` runs a saved screen module in an iframe with `sandbox="allow-scripts"` and no same-origin, form, popup, or top-navigation permission. Its document uses a restrictive CSP: no network connections, data/blob images, leased Namespace byte URLs, and module scripts from Trillion's public `/workspace/` and `/workshop/modules/` routes. It gets the Trillion service origin from its own served module URL, so assets resolve to Trillion even when the workspace is embedded in another chat host. It keeps only same-origin public module addresses.

The module receives `mount(element, { surfaceInput, host })`. `host.call(name, input)` is the only route to account actions. The signed-in workspace validates the declared capability, fixed `/work/api/` path and method, input schema, body fills, and fixed bindings before `readJson` sends the request through the existing Worker gates. A declaration may name only a (method, path) row of `sandboxed-screen-routes.json`, read-only unless the row names its one allowed write, and only the addressed resource operations listed there (none): an allowlist, so a route nobody listed is refused. A save that names one is told why in the list's own `unlisted_words` (where the rows go instead, and that granted kinds is the road to the person's records); the running screen is told only that the request is unavailable. The door (`/work/api/door/*`), the account, logins and devices are never on it, and `test/isolated-module-surface.test.mjs` refuses a list that names them. In a space, requests require an explicitly space-scoped `/work/api/spaces/:space_id/` declaration or the canonical lesson-practice capability bound to the current community, course and lesson; there is no personal fallback.

For media, `host.mediaUrl(identity)` asks the outer trusted host to mint a one-file Namespace read lease through `POST /work/api/namespace/leases`. The host only leases a content identity already present in this screen's `surfaceInput`, and the Namespace owner still checks current access. The module receives a short-lived byte URL; it has no session credential, `fetch` access, or arbitrary network access. Images, audio and video are allowed by CSP only from Trillion's `/namespace/bytes/` path.

Request input schemas accept bounded recursive JSON: scalar values, objects with declared properties and `additionalProperties: false`, and arrays whose `maxItems` is required and at most 256. Schemas and values are limited to depth 12, objects to 128 properties, and each serialized input/body to 32 KiB. The host serializes asynchronous input updates and skips superseded queued updates. Editing inputs within one account/Space keeps the module instance and its local state; changing account or Space identity remounts it so an old screen callback cannot be rebound to a new place.

Saved screen code is public and holds no private records. Its public archive contains only the JavaScript entry named in `screen.module.file` and the additional JavaScript files explicitly named in `screen.module.files`; relative imports outside that set are refused. The full tool archive remains account-only until the tool itself is published. A screen can reach account data only through its named request declarations, which the signed-in workspace validates against `sandboxed-screen-routes.json` and executes; adding an allowed route is a row of that list, not code.

`use-lesson-practice.mjs` is the reusable React state adapter for bundled lesson modules. It uses only declared `read_practice` and `keep_practice` calls. The current lesson label selects both `records[label]` and `identities[label]`; permitted fields and their 2,000-character bounds match `lessonPracticeRequests`. A save retains untouched accepted fields, captures its intended payload and original identity once, and keeps the same request key while its outcome is uncertain. Exact scoped readback with a valid content identity is required before success; the hook and conditional-write owner share `lessonPracticeIdentity`. A conflicting version becomes the new accepted base while the learner's visible answers remain for an explicit retry. The hook accepts caller-owned message DATA and an unedited-initial-read restore callback. It is bundled into the saved entry with React external, so it does not require an additional public library export. The existing Classroom scope/bundle/file/lesson key still owns remounting across account contexts. Retained M007 source and bundles predate this extraction and remain unchanged.

Saved JavaScript imports React from `react` and the licensed shared browser components from `@trillion/ui`. That public library and `react-dom/client` / `react/jsx-runtime` are built independently of shipped screen imports. The library exports the existing UI part's public API, including `mountReactSurface`, `keepRecordViewPreferencesIn`, and `RecordViewPreferenceStore`. A saved screen that uses `RecordViews` installs this adapter before rendering: its `use` member is a React hook that reads and subscribes through a named read capability, and its `write` member calls a named write capability with `host.call`. The screen's tool row must declare those capabilities; a custom hook can keep the read result reactive. The shared component keeps its refusing default when no owner is installed, and a refused write remains a visible save failure. The named-request owner accepts the listed fixed paths (plus its explicit Space parameter) and the canonical single-lesson practice-record query built by `lessonPracticeRequests`; other query parameters remain refused. The lesson request owner and shared hook landed together at `467f56216074a89826c76dfbae5061718da0a126`, with exact immutable source readback. This source landing does not establish deployed account support; Classroom integration and real learner persistence require their own checks. Shared UI imports no account transport. Import-map entries do not fetch a module; code is loaded only when imported. Saved screens do not import private workspace implementation paths. When a shared module is renamed, its former name stays importable for a window: a row in `scripts/screen-modules-shared.json` `former_names` ({ now, until, why }) makes the workspace build point the former name at a content-named shim (`scripts/screen-modules.mjs` `formerNameShims`) that warns once in the screen's console and re-exports the current module, so the screen still shares the page's one instance; after `until` the build leaves the name out. Content-named library files remain readable after subsequent deployments.

The iframe has an opaque origin. The parent transfers one `MessagePort` to that exact frame and listens only on the port. Unlisted operations and extra input fields are refused. Shipped `{ package, entry }` screens remain on the existing in-page module path; saved `{ bundle, file }` screens use this isolated host.
