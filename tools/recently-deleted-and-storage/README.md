# tools/recently-deleted-and-storage

Recently Deleted and Archived for a person's files: `namespace-set-aside.mjs`, moved from old trillion's `src/namespace-set-aside.mjs`. Deleting or archiving takes a file's or a folder's names out of the namespace and keeps them here, with when and by whom, so Put back gives every name back exactly as it was; when a state's time ends, an archived thing moves to Recently Deleted and a deleted one's names are gone for good. Nothing here deletes bytes.

## Account metadata and wake consumer

## Which of the six old tools run

The old tools were `delete-files`, `archive-files`, `recently-deleted` (list), `put-back-files`, `read-deleted-files-keep-for` and `set-deleted-files-keep-for`. `tool:read-deleted-files-keep-for` (`tools/recently-deleted`) and `tool:set-deleted-files-keep-for` run today, from the person's `setting:keep_for` handed in as values. The other four, and the hourly sweep, need to call the files door's name operations from inside a run; since `tools/records-door/read-data/values-door.mjs` (5f435a280, Nov 18 2026) a run's door answers records and file reads from the values it was given and refuses any other files operation. `do-work/recently-deleted-actions.mjs` is written and tested for that call (`test/recently-deleted-actions.test.mjs`, 12 tests over a stand-in of the engine's rules); it waits for a door that carries the effect, or for the person's AI to make the file calls itself and hand the run what it read. Until then the person's AI deletes and puts back through the files tool (`set_aside`, `put_back`).
