# parts/eeaf

The decomposed record store every person's data lived in before the log engine (`parts/record-log`); a person's store still on it is answered from it through `src/record-engine.mjs` until `src/record-move.mjs` has moved its records across, and then its tables are dropped. Whole root records (`{ id, type, value }`) kept as entities, typed attribute facts and participations over the eleven EEAF tables, with every change appended to the bitemporal log (`bitemporal_facts`) with the time it happened.

The tables go; the model does not. The EEAF model (entity types, their properties, participation and interaction sets) is kept for every store as DATA over the log engine's records (`parts/record-log/do-work/record-model.mjs`, `src/record-model.json`), as keys of its pages rather than rows, and read through `model`, `factsOf`, `partsOf`, `holdersOf` and `membersOf` (the `read_model` tool).

## Key Types / Functions

| Name | Signature / Shape | Role |
|------|-------------------|------|
| `EEAF_CORE_TABLES` | `string[]` | The table names the store owns (a person's store leaves them out of its own table sweeps) |
| `nextEeafTable(sql)` | `(sql) → table \| null` | Names the next of the store's tables still in the database, children before the tables they reference; the host lets it go a bounded piece per step (`src/let-go-of-table.mjs`: indexes, then rows only while it is too large for one drop) and drops it, so a table no other table references is dropped without SQLite deleting its rows first and one drop never outruns a storage operation's time (`test/record-move.test.mjs`). The move calls it once the store's last log generation has been kept elsewhere |
| `createEeafTables(sql)` | `(sql) → void` | Creates the tables and indexes when missing; every column that references `entity` is indexed, so removing an entity never scans a table (`test/eeaf-deletes-search-by-index.test.mjs`) |
| `canonicalAddressString(table, row)` | `(table, row) → string` | The address a row change is logged under |
| `eeafStore(sql, { transaction, contentId, hash })` | `→ { write, read, readOwn, readMember, memberCount, memberFields, membersWhere, membersHolding, writeOwn, writeMember, typeOf, ids, find, log, held, forgetCached }` | The store. `write(records, { actor, application_time, transaction_id })` writes whole root records in one transaction (value `null` removes); `read(id)` answers one record or `null`, assembled from the rows the store keeps for it when that record was read or wholly written (`write`) before and nothing else changed it since (`writeOwn`, `writeMember` and `forgetCached` let the record go, and the store is the only writer of its database, so a repeat read, and the next whole write of a record, runs no query to find what it holds); `ids(type, { before, limit, prefix })` lists root ids, optionally within a literal prefix; `log({ transaction_id \| record_id })` reads the log |
| `find({ words, fields, leaveOut, limit })` | `→ [{ id, type, title }]` | Root records of EVERY type whose words at one of `fields` (paths of field names, `[["title"], ["input", "goal"]]`) hold every one of `words`, newest named first, each titled by its first named field; `leaveOut` names types never answered. Reads only the named fields' facts by property, never whole records. What `@` offers of a person's own records (`src/person-store.mjs` POST `/records/find`, `src/work-mentions.mjs`), so a kind of record nobody listed is offered the day it is kept |
| `changeSeq()`, `changedSince(seq)` (now `src/record-engine.mjs`) | `→ number`, `→ string[] \| null` | Kept by the store handed to callers for both engines, no longer here. The record store's change journal: every root record written (any type, through any store opened over the same database) takes the next number; `changedSince` names the roots written after `seq`, or null when the journal (at most 20 000 roots, then it starts again from a floor) no longer reaches back, so the caller reads everything. A view kept over many records works out only those again: `src/person-store.mjs` whatHelped over every decided decision |
| `held()` | `() → { known, shared, records }` | How much the store holds in memory now. All are bounded (`KNOWN_KEPT` 20000 made-sure-of rows, then it starts again; `SHARED_KEPT` 500 assembled shared objects, oldest let go first; `records` is the memory of the rows of whole records `read` or `write` already handled, `RECORDS_KEPT` 4000 records or 8 MB of the memory their rows take (every id, property and value string plus a fixed cost per row, never only the value text), a record over 256 KB is never kept), because a store lives as long as its Durable Object and every write adds to them; a forgotten row costs one indexed check the next time a write needs it |
| `eeafFieldReads(sql)` | `→ { fieldsOf, after, newestPerGroup, idsWhere }` | Field reads over the same SQLite: `fieldsOf(type, ids, fields)` → `Map(id → { id, ...fields })` (an id not held as `type` is left out); `after(type, field, after, fields, { limit? })` → the records whose `field` sorts after `after`, oldest first, at most `limit` when given; `newestPerGroup(type, { group, order, fields })` → one record per value of `group`, the one with the largest `order`; `idsWhere(type, field, value)` → ids whose `field` is exactly `value`. Top-level fields only; values decoded from JSON, compared as kept (ISO times sort). Used by `src/automations.mjs` readHealth (arrivals), `src/messages.mjs` correctProvenance and `src/decision-store.mjs` callsAt (a decision's calls, each as the few fields a count reads), and `src/awareness.mjs` awarenessInputs (messages kept since its last reading, a page at a time) |
| `oldestLogId()`, `sealLog()`, `sealedLogs()`, `sealedLogPage(table, after, limit, maxBytes)`, `dropSealedLog(table)` | `→ id \| null`, `→ table \| null`, `→ tables`, `→ { rows, last, rowids }`, `→ void` | The log moves out a whole generation at a time: the open log's oldest id; sealing it (renamed after its first row, a fresh empty log opened in the same transaction); the sealed tables oldest first; a sealed table's rows after a rowid in the order they were written (`last` is the rowid to continue after, `rowids[n]` each row's own; `maxBytes` bounds the page before full rows are read, sizing rows by `octet_length` from their headers); and dropping a sealed table once the host has kept every row. A host keeps the rows elsewhere first: a person's store moves changes older than keep_days out as files (`src/record-history.mjs`), since the log grows with every write and filled a 10 GB store on 2026-10-03. A dropped table costs no row written where deleting rows costs one each, and the log tables carry no key or index, so each logged change is one row written |
| `logIdAt(ms)` | `(ms) → string` | The first log id of a moment: every log id written before it sorts lower, since log ids are time-ordered (UUIDv7); owned by `parts/record-log` and re-exported, so both engines number their logs alike |
| `RECORD_BOUNDS` | `{ rows, bytes }` | How large one record may grow before it is refused rather than read (30,000 rows, 8 MB of value text: thousands of times any record kept today). `eeafStore(sql, { bounds })` sets others |
| `RecordTooLarge` | `Error { code: 'record_too_large', record_id, size }` | Owned by `parts/record-log` and re-exported, so either engine's refusal is the same error. Thrown by `read` (and by a write or shared-part read of that record) when it is past its bounds, before any of its rows are read; `size.by_field` names the top-level fields it grew under. One oversized record fails alone instead of taking the memory of the whole database. A shared part that contains itself is refused too, never read forever |
| `readOwn(id, except)`, `readMember(id, field, ordinal)`, `memberCount(id, field)` | `→ object \| null`, `→ object \| null`, `→ number` | One record read a part at a time: its fields without the top-level fields named in `except` (their rows are never read), one object of its list `field`, or how many that list holds. `src/decision-store.mjs` reads a decision kept whole this way (its own fields, one answered step), so answering it never reads every earlier answer and try. Held to the record's bounds like `read` |
| `memberFields(id, field, names, ordinals?)`, `membersWhere(id, field, name, value)`, `membersHolding(id, field, name)` | `→ [{ ordinal, ...names }]`, `→ number[]`, `→ number[]` | Facts about the objects of one list without reading them: their top-level scalar `names` (all objects, or those at `ordinals`); the ordinals whose scalar `name` is exactly `value`; the ordinals that hold anything at `name` (a value, an object or a list), found by point lookups |
| `writeOwn(id, type, value, except, context)`, `writeMember(id, type, field, ordinal, value, context)` | `→ { transaction_id }` | One record written a part at a time, logged like `write`: its own fields, leaving the fields named in `except` as they are (never read); or one object of its list `field`, replacing the object at `ordinal` or, at the next ordinal, adding it to the end (the list, its link and its membership made as needed; an empty list kept as `[]` gives way). Only that object's rows are read and changed |
| `sizeOf(id)` | `(id) → { rows, bytes, entities, facts, parts, members }` | What one record holds, counted by SQLite without reading it. `typeOf(id)` likewise reads only the record's type row |
| `forgetCached()` | `() → void` | Drops what the store remembered of rows it made sure of, shared objects it read and whole records it assembled. A write that throws calls it itself; a host whose OUTER transaction rolls back after a write here must call it (the person's store does, in `PersonStore.transaction`), or the next write trusts rows that are gone and fails a foreign key |

## Dependencies

**Depends on:** `parts/record-log` (`RecordTooLarge`); the host passes `sql`, `transaction` and the `hash` identity function.

**Depended on by:** `src/record-engine.mjs` (answers a store still on these tables, its field and index reads, and its sealed log generations after the switch), `src/record-move.mjs` (reads the records it moves, seals the last generation, drops the tables), and through those `src/decision-store.mjs`, `src/record-history.mjs` and `src/person-store.mjs`.

## The row

`tool:read-named-fields-of-many-records` runs `do-work/read-fields-of-records.mjs` in a small container with no internet. `eeaf-sqlite-store.mjs` cannot be loaded in the Workshop: it imports `../../record-log/do-work/record-log-store.mjs`, which `tools/record-log` does not hold (the old file is 4456 lines with its own imports, too large to bring in). The row therefore reads only the store's table statements from it as text and answers field reads; it does not write, log or assemble records.
